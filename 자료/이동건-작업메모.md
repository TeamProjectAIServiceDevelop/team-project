# 이동건(AI) 작업 메모 — 집에서 이어 하기

2026-11-04 · `feat/ai` 브랜치 기준

## 1. 집에서 시작하기

```bash
git clone https://github.com/TeamProjectAIServiceDevelop/team-project.git
cd team-project
git switch feat/ai
npm install
```

GitHub에 **없는** 것은 직접 옮기거나 다시 만들어야 한다.

| 필요한 것 | 방법 |
| --- | --- |
| 평가 사진 9장 (`eval/data/mega/images/mega-001.png` ~ `mega-009.png`) | 용량 때문에 `.gitignore`로 제외돼 있다. 공유 드라이브나 USB로 옮겨 같은 경로에 넣는다. 사진이 없으면 `labels.jsonl`이 있어도 평가가 안 된다. |
| `.env.local` | `.env.example`을 복사해 아래처럼 채운다. |
| Ollama와 모델 | Ollama를 설치하고 `ollama pull qwen2.5vl:7b`(약 6GB). GPU가 없으면 매우 느리다. |

```
KIOSK_AI_MOCK=0
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5vl:7b
```

자주 쓰는 명령:

```bash
npm run dev                                   # 처음엔 Next.js 업그레이드 권고가 뜨며 한 번 종료된다. 다시 실행하면 정상 기동한다(업그레이드는 하지 않았다).
npm run eval -- --data eval/data/mega --name 이름 --pixels 980000   # 평가. 앱(app/frame.ts)과 같은 크기로 보낸다.
npm run label -- --data eval/data/1차          # 라벨링 도구 (사진을 images/에 넣고 켠다)
```

## 2. 지금까지 한 것

- `lib/guide.ts`: 응답에 `confidence` 추가, 버튼 목록(`steps`)이 비고 주문이 안 끝났으면 안내문을 "다시 비춰 주세요" 고정 문구로 교체, 검증 단계용 함수(`cropRegion`, `buildVerifyMessages`, `parseVerify`, `rejectGuide`).
- `app/api/guide/route.ts`: 3단계 검증(상자 부분을 잘라 그 버튼이 맞는지 재확인). **기본은 꺼짐**, `KIOSK_VERIFY=1`일 때만 동작한다. `sharp`를 서버에서 쓰므로 `package.json`의 일반 의존성으로 옮겼다.
- `eval/`: 평가 스크립트(`run-eval.mjs`, `--pixels` 옵션, 확신도별·보여 준 안내의 정밀도 출력), 라벨링 도구(`label-server.mjs`), 라벨 49문항(`data/mega/labels.jsonl`).
- `자료/`: 메뉴 읽기 프롬프트 제안, 시연 점검 목록.
- `master`에는 `feat/web`이 병합돼 있고, `feat/ai`는 그 `master`를 병합한 상태다(충돌 해결 완료).

## 3. 현재 수치

49문항, Qwen2.5-VL 7B, 사진을 약 98만 픽셀(28의 배수로 내림)로 보냄. 라벨은 직접 붙인 것이고 한 종류의 키오스크(메가엠지씨)에서 어려운 곳을 일부러 많이 넣어서 실제보다 낮게 나올 수 있다.

| 지표 | 값 | 목표 |
| --- | --- | --- |
| 버튼 이름 맞음 | 73.5% (36/49) | 70% |
| 위치 맞음 | 57.1% (28/49) | 60% |
| 이름·위치 둘 다 맞음 | 약 26~27/49 (53~55%) | |
| 응답 시간 | 평균 약 3초 | 5초 |

- 확신도는 49문항에서 믿기 어렵다. `high`인데 틀린 것이 15개였다.
- 16문항일 때 나온 87.5%, 81.3%는 쉬운 문항이 많아서 낙관적이었다. 인용하지 않는다.

## 4. 알아낸 것 (잊지 말 것)

- **Ollama는 보낸 사진 크기와 상관없이 이미지를 안쪽에서 약 100만 픽셀로 바꾸고, 모델은 그 크기 기준 좌표를 낸다.** 작은 사진을 그대로 보내면 좌표가 어긋나 위치 정확도가 0%가 된다. 28의 배수이면서 98만 픽셀 이하(Ollama 상한 1,003,520)로 맞추면 좌표가 맞는다. 정윤서가 `app/frame.ts`에 같은 방식(내림)을 이미 넣었다.
- **사진 크기가 28픽셀만 달라도 모델 답이 달라진다.** 평가도 반드시 앱과 같은 방식(내림)으로 보내야 점수가 앱의 정확도를 뜻한다. 같은 사진·같은 코드는 같은 결과가 나온다(결정적).
- **3B는 이 PC의 Ollama 0.40.12에서 구조화 출력이 중간부터 깨진다**(`Unexpected empty grammar stack`). 한 번 실패하면 이후 요청도 전부 실패한다. 당분간 7B를 쓴다. Ollama를 최신으로 올리면 풀리는지는 아직 확인 못 했다.
- 프롬프트에 "상자가 없으면 다시 비추라고만 말해라"를 넣어도 모델이 따르지 않았다(16문항 중 1개). 그래서 코드가 고정 문구를 정한다.
- 흐림에 약하다. 약한 흐림만 줘도 정답이 반 이하로 떨어진다. 선명한 프레임만 AI에 보내는 것(웹 쪽)이 가장 확실한 대책이다.
- 2단계(판단 → 위치 찾기)는 약 4초(생성 시간이 대부분)다. 출력을 줄이는 것은 효과가 8% 정도라 적용하지 않았다.

## 5. 진행 중이던 일 / 다음에 할 일

**검증 단계 (정확도 개선 실험)** — 49문항, 같은 파이프라인 기준

| 방법 | 안내를 보여 줌 | 맞음 | 틀린 안내 |
| --- | --- | --- | --- |
| 검증 없음 | 49 | 26~27 | 22~23 |
| 확신도 `high`만 | 34 | 19 | 15 |
| 예/아니오로 검증(조각을 잘라서) | 23~30 | 18~20 | 5~12 |
| 예/아니오로 검증(전체 사진에 좌표만 말함) | 39 | 26 | 13 |

- 예/아니오 방식은 틀린 안내를 줄이지만 맞는 안내도 약 8개 거른다. 비슷한 칸이 나란한 곳(결제수단 로고)에서는 쉽게 "예"라고 답해 11개를 못 걸렀다.
- **멈춘 시점**: 조각에 적힌 글자를 읽게 하고, 읽은 글자가 안내한 버튼 이름과 같은지 코드로 비교하는 방식을 시험하던 중이었다(여백 10%와 25% 비교). 이름이 다른 옆 칸을 걸러 낼 것으로 기대했다. 아직 결과가 없다. 스크립트는 지웠으니 위 설명대로 다시 만든다.
- 새 매장·새 키오스크 사진을 모아 문항을 늘린다(매장 10곳 이상, 사진 200장 이상이 목표). 라벨링 도구로 한다.
- 모델 비교(7B, 3B, 상용 API)는 사진이 모인 뒤에 한다고 정했다.
- 상용 API 대체 경로(Tunnel이나 PC가 꺼질 때의 비상구)는 아직 없다. API 키가 필요하다.

**정윤서(웹)에게 전달할 것**

- Vercel 환경변수: `OLLAMA_URL`(Tunnel 주소), `OLLAMA_MODEL=qwen2.5vl:7b`, `KIOSK_AI_MOCK=0`. 바꾼 뒤 **재배포**해야 적용된다. (확인했을 때는 배포 앱이 AI 서버에 연결돼 있었다.)
- 응답의 `confidence`를 쓰는 처리(`low`/`medium`이면 상자를 숨기고 다음 장면을 다시 분석). 단, 확신도만으로는 틀린 안내를 거의 못 거른다.
- 메뉴 읽기 프롬프트 개선안: `자료/메뉴읽기-프롬프트-제안.md`. 현재 프롬프트는 메뉴 화면 6장 중 1장만 읽는다.
- Vercel이 어느 브랜치를 배포하는지(문서에 없다).

## 6. 이 PC에만 있는 것

- 평가 사진, `.env.local`, Ollama와 모델, 개발 서버.
- **Cloudflare 임시 Tunnel**: 배포 앱이 이 PC의 Ollama에 닿는 통로다. 이 PC가 꺼지거나 절전에 들어가거나 Tunnel을 다시 켜면 배포 앱의 AI가 끊기고 주소가 바뀐다(Vercel `OLLAMA_URL`을 고쳐 재배포해야 한다). 고정 주소는 도메인이 필요해서 만들지 않았다. 시연 전 점검은 `자료/시연-점검목록.md` 참고.
- 이 작업을 하던 대화 맥락. 필요한 내용은 이 문서에 정리했다.

## 7. 결과 읽는 법

- `npm run eval` 출력에서 **"버튼 안내 정확도"**는 AI가 말한 버튼 이름이 정답과 같은 비율이고, **"위치 정확도"**는 AI 상자의 중심이 정답 상자 안에 있는 비율이다. 둘은 따로 센다. 사용자에게는 둘 다 맞아야 길 안내가 된다.
- 마지막의 "안내를 보여 준 문항 … 이름·위치 둘 다 맞음"이 사용자 입장의 정밀도다(검증 단계가 안내를 거둔 문항은 빠진다).
