# 키오스크 주문 안내 AI 프로젝트 정리

## 1. 구현 가능성

Qwen으로 키오스크 주문 방법을 안내하는 기능은 충분히 구현할 수 있다. 다만 처음부터 학습(파인튜닝)이 꼭 필요하지는 않다.

- 일반 Qwen은 텍스트만 이해한다.
- 키오스크 **화면 이미지**를 보고 판단하려면 **Qwen-VL 계열**(예: Qwen2.5-VL) 같은 비전-언어 모델이 필요하다.

### 방법 1: 학습 없이 프롬프트로 (가장 먼저 시도)

키오스크를 직접 만든다면 화면 이미지 대신 **현재 화면 상태를 데이터로** 넘기는 것이 더 정확하고 쉽다.

```json
{
  "현재화면": "메뉴 선택",
  "버튼": ["버거", "음료", "사이드", "장바구니", "결제하기"],
  "장바구니": ["불고기버거 1개"]
}
```

- 이 데이터 + 사용자 질문("콜라 추가하려면 어떻게 해?")을 텍스트 Qwen에 전달
- 예시 답변: "'음료' 버튼을 누른 뒤 콜라를 선택하세요"
- 메뉴 정보나 주문 절차 설명서를 함께 넣으면(RAG) 더 정확해진다.

### 방법 2: 화면 이미지 + Qwen-VL (학습 없이)

- 화면 캡처를 Qwen-VL에 주고 "이 화면에서 결제하려면 어디를 눌러야 해?"라고 질문
- 학습 없이도 버튼을 꽤 잘 찾는다.
- 화면 구조 데이터를 넘기기 어려운 경우(다른 회사 키오스크 등)에 적합

### 방법 3: 파인튜닝 (위 방법이 부족할 때)

특정 키오스크 디자인에 맞춰 정확도를 높이고 싶을 때 **LoRA 파인튜닝**을 한다.

- 입력: 화면 캡처 + 질문 ("아이스 아메리카노 주문하려면?")
- 출력: 정답 안내 ("1. 커피 탭 선택 → 2. 아메리카노 → 3. ICE 선택") 또는 버튼 좌표
- 화면마다 다양한 질문으로 수백~수천 개 데이터 준비
- 도구: LLaMA-Factory, ms-swift 등
- GPU 메모리가 많이 필요하므로 작은 모델(3B, 7B급)부터 시작

### 추천 순서

방법 1로 먼저 동작하는 것을 만들고, 차별점이 필요하면 방법 2·3을 추가한다.

## 2. 비용 문제

핵심은 학습 여부가 아니라 **모델을 어디서 실행하느냐**이다.

| 실행 방식 | 비용 |
|---|---|
| API (알리바바 클라우드 등) | 호출할 때마다 토큰 단위 과금 |
| 로컬 (Ollama, LM Studio, vLLM 등) | 추가 요금 없음 (전기세·장비 비용만) |

- Qwen은 모델 파일이 공개된 오픈 모델이라 직접 설치해서 무료로 쓸 수 있다.
- 파인튜닝한 모델도 어딘가에서 실행해야 하는 건 같다. 학습 시 GPU 비용이 추가될 뿐이다.
- **학습 여부와 상관없이 로컬로 돌리면 무료.**

### 로컬 실행 예시

1. Ollama 설치 후 `ollama run qwen2.5:7b` 실행 (사양이 낮으면 `3b`, `1.5b`)
2. 키오스크 프로그램에서 `localhost`로 Ollama에 요청
3. 화면 상태 JSON + 질문을 넣어 안내 답변 받기

## 3. 앱으로 만들 때 무료로 가능한가

| 방법 | 설명 | 비용 | 적합한 경우 |
|---|---|---|---|
| 휴대폰에서 직접 실행 | 작은 Qwen(0.5B~1.5B)을 앱에 넣어 실행 (llama.cpp, MLC LLM) | 무료 | 앱 하나로 독립 동작을 보여주고 싶을 때 |
| 노트북을 서버로 사용 | 노트북의 Ollama에 앱이 요청 | 무료 | 팀 프로젝트·시연 |
| 클라우드 GPU 서버 | 실제 서비스용 서버 운영 | 보통 유료 | 실제 출시 |

### 방법별 참고

- **휴대폰 실행**: 서버·인터넷 불필요. 단, 앱 용량이 1GB 안팎으로 커지고 구형 폰에서는 느리거나 발열. 답변 품질이 7B급보다 낮음.
- **노트북 서버**: 같은 와이파이에서는 노트북 IP로 연결. 외부 접속은 Cloudflare Tunnel이나 ngrok(무료 플랜) 사용. 노트북이 켜져 있어야 동작.
- **클라우드**: 무료 크레딧은 일시적이며 계속 무료 운영은 어렵다.

## 4. 인공지능 서비스 개발 주제로 적합한가

### 좋은 점

- **사회적 필요가 분명함**: 고령자·장애인·외국인의 키오스크 사용 어려움(디지털 격차)
- **사용 시나리오가 명확함**: "아이스 아메리카노 주문하고 싶어" → 단계별 안내, 시연 시 바로 이해됨
- **여러 AI 기술 조합 가능**: LLM, 비전, 음성(STT/TTS)

### 주의할 점

- 키오스크를 직접 만들고 안내를 넣으면 AI 역할이 약해 보일 수 있다. ("안내 문구를 그냥 코딩하면 되지 않나?")
- 프롬프트만 넣은 수준이면 "챗봇 하나 붙인 것"으로 보일 수 있다.

### 주제를 강하게 만드는 방법

1. **실제 키오스크를 카메라로 인식**: 휴대폰 카메라로 아무 매장 키오스크를 비추면 Qwen-VL이 화면을 읽고 "오른쪽 아래 '포장' 버튼을 누르세요"라고 안내. 처음 보는 키오스크에도 동작해야 하므로 AI가 꼭 필요하고, 파인튜닝할 명분도 생김.
2. **음성 대화 추가**: 글자 읽기가 어려운 사용자를 위해 말로 묻고 말로 안내.
3. **성능 평가**: 학습 전후 또는 모델 크기별로 "올바른 버튼을 안내한 비율" 같은 지표 비교.

### 결론

"내가 만든 키오스크 + 안내 챗봇"보다 **"어떤 키오스크든 카메라로 비추면 음성으로 주문을 도와주는 앱"**으로 방향을 잡으면 AI 서비스 주제로 훨씬 적합하다.
