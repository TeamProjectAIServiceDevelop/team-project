# 최종 발표(12월 2일) 할 일

2026-11-27 작성 · 이동건, 정윤서

발표는 학습한 3B 모델(`kiosk-3b-button`)로 한다. 이 문서는 발표 전까지, 전날, 당일에 할 일을 순서대로 적은 것이다. 위에서부터 차례로 체크한다. 이전의 `시연-점검목록.md`(11-04, 7B 기준)를 대신한다.

## 1. 발표 전까지 (~12/1)

### 모델 적용

- [ ] **AI 서버 PC(학교 3060)에 모델 등록** — 이동건
  - `kiosk-3b-button-ollama.zip`(4.6GB)을 옮겨 풀고 `ollama create kiosk-3b-button -f Modelfile`
  - `ollama run kiosk-3b-button`에 서로 다른 키오스크 사진 두 장을 연달아 넣어 둘 다 한글 버튼 이름이 나오는지 본다. `888…`이 나오면 mmproj가 f32 파일인지 확인한다.
  - 자세한 방법: [파인튜닝_모델_적용_가이드.md](파인튜닝_모델_적용_가이드.md) "지금 모델"
- [ ] **학교 PC에서 다시 채점** — 이동건
  - 41문항(`finetune/eval-ollama.ts`, `feat/ai` 브랜치): 이름+위치 32개 안팎이면 정상이다.
  - 49문항(사진이 학교 PC에만 있음): 중간발표의 7B 결과(이름 36, 위치 28)와 같은 문항으로 비교한다.
- [ ] **Vercel 환경변수 변경 · 재배포** — 정윤서
  - `OLLAMA_MODEL=kiosk-3b-button`, `OLLAMA_URL=<터널 주소>` → Deployments에서 **Redeploy**
  - 휴대폰으로 https://kiosson.vercel.app/ 을 열어 안내와 상자가 나오는지 확인
- [ ] **배포 브랜치 정리** — 공동
  - 학습·평가 코드가 있는 `feat/ai`와 웹 변경이 있는 `feat/web`을 master로 Pull Request 병합한다. 발표 때 보여 줄 저장소 상태가 master여야 한다.

- [ ] **대체용 시연 영상 녹화**: 휴대폰 화면을 녹화하면서 주문 한 건을 처음부터 결제 직전까지 끝낸다.

### 시연 준비

- [ ] 시연할 키오스크 화면을 정한다. 실제 매장이면 촬영 허락을 받고, 아니면 모니터에 키오스크 사진을 띄운다(학습한 메가커피 화면이 가장 잘 된다).
- [ ] 그 화면으로 처음부터 끝까지 한 번 해 본다. 반사가 심하면 각도나 모니터 밝기를 바꾼다.
- [ ] Android Chrome과 iPhone Safari에서 각각 해 본다. 음성 인식이 안 되면 글자 입력으로 한다.
- [ ] 터널을 다시 켜고 Vercel 주소를 바꿔 재배포하기까지를 한 번 연습해 걸리는 시간을 잰다.

## 2. 발표 전날

### AI 서버 PC

- [ ] 윈도우 절전 · 화면 끄기 · 덮개 닫기 동작을 **끔**으로 둔다. 절전에 들어가면 터널이 끊긴다.
- [ ] 전원 어댑터를 꽂아 둔다.
- [ ] `ollama list`에 `kiosk-3b-button`이 있다.
- [ ] 모델을 한 번 부른 뒤 `ollama ps`에서 `PROCESSOR`가 `100% GPU`인지 본다.
- [ ] 게임, 영상 편집, 학습 등 GPU를 쓰는 프로그램을 끈다.
- [ ] Ollama 자동 업데이트를 끈다. 지금 확인된 버전은 0.40.16이다.

### 터널 · 배포

- [ ] 터널을 켠다.
  ```
  cloudflared tunnel --url http://localhost:11434 --http-host-header="localhost:11434"
  ```
- [ ] 바깥에서 닿는지 확인한다. 모델 목록에 `kiosk-3b-button`이 나오면 정상이다.
  ```
  curl https://<터널 주소>/api/tags
  ```
- [ ] Vercel 환경변수를 확인하고 재배포한다.
  ```
  OLLAMA_URL=<터널 주소, 끝에 / 없이>
  OLLAMA_MODEL=kiosk-3b-button
  KIOSK_AI_MOCK=0
  ```
- [ ] 터널 주소는 팀 밖에 공개하지 않는다. 주소를 아는 사람은 누구나 우리 Ollama를 쓸 수 있다.

## 4. 문제가 생기면

위에서부터 쓴다.

| 상황 | 할 일 |
|---|---|
| 503 "AI 서버에 연결하지 못했어요" | 터널이 꺼졌거나 주소가 바뀜. 터널을 켜고 Vercel `OLLAMA_URL` 수정 후 Redeploy |
| 502 "AI 서버 오류 (404)" | 모델 이름 오타. `ollama list`와 Vercel `OLLAMA_MODEL` 비교 |
| 502 "화면을 잘 읽지 못했어요"가 바로 뜸 | `ollama stop kiosk-3b-button` 후 다시 요청. 안 되면 PC 재시작 |
| 학습한 3B가 이상함 | Vercel `OLLAMA_MODEL`을 `qwen2.5vl:7b`로 되돌리고 Redeploy(이전 모델은 서버에 그대로 있음) |
| AI 서버를 못 살림 | `KIOSK_AI_MOCK=1` 목업 모드로 화면 흐름만 보여 준다. 목업이라고 말하고 쓴다 |
| 모두 실패 | 녹화한 시연 영상으로 발표 |

## 5. 질문 대비

- **78%면 높은 것 아닌가?** 확인용 사진 2장은 학습에 넣지 않았지만 학습 사진과 같은 매장 · 같은 키오스크에서 연달아 찍은 것이다. 처음 보는 매장에서는 더 낮을 수 있고, 다른 매장 사진으로 재는 것이 다음 단계다.
- **왜 7B가 아니라 3B인가?** 3B는 8GB GPU에서도 학습할 수 있어 우리 데이터로 직접 고칠 수 있다. 학습한 3B가 원본 7B보다 정답이 두 배 넘게 많고, 응답도 3.4초에서 1.9초로 빨라졌다.
- **사진은 저장하나?** 저장하지 않는다. 피드백(맞았어요/틀렸어요)만 저장한다.
- **흐린 화면은?** 약한 흐림에서도 정답이 절반 이하로 떨어진다. 휴대폰이 멈춰 있을 때만 장면을 보내는 것으로 일부 막고, 선명한 프레임만 보내는 것은 남은 과제다.
- **서버가 꺼지면?** 지금은 개인 PC와 임시 주소다. 실제 서비스에는 고정 서버와 상용 API 비상 경로가 필요하다.
