# 팀플 아이디어 상세 기술 — 키오스크 길잡이

2026-10-07 · 이동건, 정윤서

## 1. 아이디어

**키오스크 길잡이**는 고령층이 처음 보는 매장 키오스크 앞에서 휴대폰 카메라를 비추고 원하는 주문을 말하면, AI가 화면을 읽고 지금 눌러야 할 버튼 하나를 화면 표시와 음성으로 알려 주는 모바일 웹 서비스다.

### 주 대상

주 대상은 고령층이다. 작은 글씨, 매장마다 다른 화면, 많은 단계 때문에 주문을 포기하거나 뒷사람 눈치를 보는 사람이 도움 없이 혼자 주문을 끝내도록 돕는다.

### 작동 방식: 턴 방식으로 시작해 실시간으로 확장

1. **1단계 (기본, 턴 방식)**: 사용자가 "아이스 아메리카노 한 잔 포장"처럼 주문을 말하고 키오스크 화면을 찍는다. AI가 화면이 메뉴 선택, 옵션, 결제 중 어느 단계인지 파악하고 다음 버튼을 고른다. 사진 위에 그 버튼을 빨간 상자로 표시하고 "오른쪽 아래 '커피' 버튼을 누르세요"라고 읽어 준다. 사용자가 "눌렀어요"를 누르면 바뀐 화면을 다시 찍는다.
2. **2단계 (자동 촬영)**: 카메라 미리보기를 계속 켜 둔다. 휴대폰에서 작게 줄인 프레임끼리 비교해, 키오스크 화면이 바뀐 뒤 0.5\~1초 멈추면 자동으로 찍어 AI에 보낸다. "눌렀어요" 버튼은 대비책으로 남긴다.
3. **3단계 (실시간 표시)**: 빨간 상자를 실시간 카메라 화면 위에 띄운다. OpenCV.js 특징점 추적으로 휴대폰이 흔들려도 상자가 버튼을 따라간다. 선택 기능으로 MediaPipe 손 추적을 써서, 손가락이 목표 버튼에 닿은 뒤 화면이 바뀌면 자동으로 다음 단계로 넘어간다.

**핵심 설계 원칙**: 무거운 비전-언어 모델(VLM)은 화면이 바뀔 때만 호출하고(주문 1회에 5\~10회 목표), 매 프레임 처리는 휴대폰의 가벼운 연산이 맡는다. 같은 화면은 결과를 캐시해 다시 쓴다. VLM이 생각하는 동안에는 "화면을 확인하고 있어요"라고 음성으로 알려 준다.

### 핵심 기술

| 기능 | 기술 |
| --- | --- |
| 처음 보는 키오스크 화면 이해, 버튼 좌표 찾기 | 비전-언어 모델: Qwen2.5-VL 3B(로컬, Ollama), GPT 또는 Gemini 계열 API |
| 화면 변화 감지, 상자가 버튼 따라가기 | 휴대폰 브라우저의 프레임 비교, OpenCV.js 특징점 추적 |
| 손가락이 버튼에 닿았는지 확인(선택) | MediaPipe 손 추적 |
| 말로 묻고 말로 듣기 | Web Speech API (음성 인식 STT, 음성 합성 TTS) |
| 모바일 웹, API 서버 | Next.js, TypeScript, Tailwind, Vercel 배포 |
| 안내 기록, 사용자 피드백 저장 | Neon Postgres |

### 모델

- 개발 GPU는 RTX 4060 Ti 8GB다. 로컬 모델은 Qwen2.5-VL 3B를 Ollama로 실행한다.
- 상용 API(GPT 또는 Gemini 계열)도 연결해 로컬 모델과 정확도·응답 시간·비용을 비교한다.
- 배포 버전은 안정성을 위해 API를 기본으로 쓰고, 로컬 모델은 비교 실험과 대비책으로 둔다.
- 8GB에 맞는 더 최신 소형 VL 모델(예: Qwen3-VL 소형)도 후보로 둔다 (확인 필요).
- 정확도는 프롬프트 설계, few-shot 예시와 이미지 보정 순서로 높이고, 그래도 부족하면 LoRA 파인튜닝을 한다.

**환각 대비책**: VLM이 낸 JSON 좌표를 서버에서 검증한다. 좌표가 이미지 범위 안인지, 버튼 문구가 화면 글자와 맞는지 확인한다. 확신이 낮으면 "다시 비춰 주세요"라고 하거나 후보 버튼 2개를 보여 준다.

### 음성 입력이 어려울 때

음성 인식이 안 될 때를 대비해 자주 쓰는 주문(커피, 햄버거 세트 등)을 큰 버튼으로 고르는 방식도 함께 제공한다.

### 선택 기능: 집에서 미리 연습하기

매장 키오스크 사진으로 집에서 미리 주문을 연습하는 모드를 둔다. 실제 매장에서 처음 해 보는 부담과 뒷사람 눈치를 줄인다.

### 학습 데이터

유튜브의 키오스크 사용 영상을 재생 화면 캡처로 모은다(다운로드 도구는 쓰지 않는다). 크리에이티브 커먼즈 영상과 공공기관 교육 영상을 우선 쓰고, 비영리 수업 목적으로 팀 내부에서만 쓰며 영상마다 출처를 기록한다. 학습과 평가는 브랜드(키오스크 종류) 단위로 나눠, 평가에는 학습에 쓰지 않은 키오스크만 써서 처음 보는 키오스크에서의 성능을 확인한다.

### 성능 측정

| 지표 | 내용 |
| --- | --- |
| 버튼 안내 정확도 | 올바른 버튼을 안내한 비율 |
| 위치 정확도 | 예측 좌표가 정답 버튼 안에 들어간 비율 |
| 주문 완료율 | 안내만 따라 주문을 끝까지 마친 비율 |
| 응답 시간 | 촬영부터 안내까지 걸린 시간 (목표 5초 이내) |
| VLM 호출 횟수·비용 | 주문 1회당 호출 횟수와 비용, 턴 방식과 자동 촬영 비교 |
| 화면 변화 감지 정확도 | 자동 촬영이 화면 전환을 맞게 잡아낸 비율 |
| 로컬 모델 vs API | 정확도, 응답 시간, 비용 비교 |

## 2. 필요성

키오스크는 빠르게 늘고 있지만, 고령층의 절반 이상은 쓰다가 어려움을 겪고 기존 해결책은 이미 설치된 기기를 바로 돕지 못한다.

### 키오스크는 늘고 있다

- 국내 키오스크는 2019년 18만 9,951대에서 2022년 45만 4,741대로 3년 사이 2.4배가 되었다. 같은 기간 요식업은 5,479대에서 8만 7,341대로 17배 늘었다(과학기술정보통신부, [이투데이](https://www.etoday.co.kr/news/view/2267919)).
- 카페, 패스트푸드점, 영화관, 병원에서는 키오스크를 쓰지 않고 주문하기가 점점 어려워지고 있다.

### 고령층은 쓰기 어렵다

서울 고령층(55세 이상)의 59.6%가 키오스크를 쓰다 어려움을 겪었고, 나이가 많을수록 이용 경험 자체가 급격히 낮아진다.

| 연령 | 키오스크 이용 경험률 |
| --- | --- |
| 55\~64세 | 79.1% |
| 65\~74세 | 50.4% |
| 75세 이상 | 19.1% |

출처: 서울디지털재단, 2023 서울시민 디지털역량실태조사 ([주간경향](https://weekly.khan.co.kr/article/202504230600051))

글씨가 작고, 매장마다 화면 구성이 다르고, 단계가 많다는 점이 주된 원인이다. 뒷사람 눈치가 보여 주문을 포기하는 경우도 많다.

보건복지부의 2024년 장애인차별금지법 이행 실태조사에서도 같은 어려움이 드러난다. 장애인 키오스크 이용자의 44.8%가 키오스크보다 직원을 통한 주문을 선호했고, 불편 사항으로 "뒷사람 눈치가 보임"(54.0%)과 "버튼 위치 찾기나 메뉴 선택·이동의 어려움"(26.1%)이 꼽혔다([뉴시스](https://www.newsis.com/view/NISX20250807_0003282770)). 장애인 대상 조사이지만, 고령층이 겪는 것과 같은 종류의 어려움을 보여 주는 참고 자료다.

### 기존 해결책의 한계

| 해결책 | 한계 |
| --- | --- |
| 배리어프리 키오스크 | 2026년 1월 28일부터 의무화됐지만 기기를 교체해야 해서 보급이 더디다. 경기도 227대, 서울 552대에 그친다([경인일보](https://www.kyeongin.com/article/1758044)). |
| 키오스크 연습 앱·교육 | 미리 만든 가상 화면으로 연습하므로, 실제 매장의 다른 화면 구성에는 그대로 통하지 않는다. |
| 직원·가족의 도움 | 무인 매장이나 바쁜 시간에는 도움을 받기 어렵다. |

그래서 **키오스크를 바꾸지 않고, 사용자의 휴대폰만으로, 지금 서 있는 키오스크 앞에서** 바로 도움을 주는 방법이 필요하다. 매장마다 다른 화면을 미리 등록할 수 없으므로, 처음 보는 화면을 읽고 판단하는 AI가 꼭 필요하다.

## 3. 대박성

쓸 사람은 천만 명 단위인데, 매장·기기 제조사와 협약 없이 휴대폰 링크 하나로 모든 키오스크에 바로 쓸 수 있다는 점이 핵심이다.

### 1) 사용자가 많고 계속 늘어난다

한국은 2024년 12월 23일 초고령사회에 들어섰다. 65세 이상이 1,024만 명으로 전체 인구의 20%다([뉴시스](https://www.newsis.com/view/NISX20241224_0003009655)). 주 대상인 고령층만으로도 쓸 사람이 천만 명 단위이고, 이 수는 계속 늘어난다.

### 2) 확장에 비용이 거의 들지 않는다

- **기기 교체 없음**: 배리어프리 키오스크처럼 매장이 돈을 들일 필요가 없다. 이미 설치된 45만 대 이상의 키오스크가 곧 적용 대상이다.
- **매장별 등록 없음**: 비전-언어 모델이 처음 보는 화면도 읽으므로 매장이 늘어도 개발비가 늘지 않는다.
- **설치 없음**: 앱스토어가 아닌 모바일 웹이라 QR코드나 링크 하나로 바로 쓸 수 있다.
- **저비용 운영 목표**: 로컬 모델(Qwen2.5-VL 3B)로 비용을 줄이되, 안정성을 위해 상용 API를 함께 쓴다. VLM은 화면이 바뀔 때만 불러 주문 1회 호출을 5\~10회로 줄이고, 웹·DB는 Vercel·Neon 무료 플랜을 쓴다.

### 3) 키오스크 밖으로 넓힐 수 있다

같은 기술로 무인민원발급기, 은행 ATM, 병원 접수기, 공항 셀프 체크인, 주차 정산기, 셀프 주유소 등 **모든 터치스크린 무인기기**를 안내할 수 있다.

### 4) 수익과 협력 모델이 보인다

- **공공(B2G)**: 지자체 디지털배움터·노인복지관의 교육 보조 도구, 관광 안내 서비스와 연계
- **기업(B2B)**: 프랜차이즈가 매장에 QR코드를 붙여 접근성을 높이는 저비용 방법으로 제공
- **데이터**: 모인 키오스크 화면·정답 버튼 데이터셋은 접근성 연구와 모델 개선에 다시 쓸 수 있는 자산이 된다.

### 5) 시연 효과가 크다

실제 매장 키오스크를 비추자 "오른쪽 아래 '포장'을 누르세요"라고 말해 주는 장면은 한 번에 이해된다. 사회적 가치(디지털 격차)와 최신 AI 기술(비전-언어 모델)을 함께 보여 줄 수 있다.

### 6) 확장 가능성: 저시력 사용자와 외국인 관광객

- **저시력 사용자**: 음성 안내와 버튼 위치 설명("오른쪽 아래")이 이미 들어 있어, 화면 글자를 읽기 어려운 사람에게 넓히기 쉽다.
- **외국인 관광객**: 2025년 방한 외국인 관광객은 1,893만 7,000명으로 역대 최대다([파이낸셜뉴스](https://www.fnnews.com/news/202602241111042813)). 한국어 키오스크 화면을 사용자의 언어로 설명하면 같은 기술로 외국인도 도울 수 있다.

## 4. 벤치마킹

카메라로 화면을 읽어 주는 서비스와 키오스크 연습 앱은 이미 있다. 처음 보는 실제 키오스크에서 주문 완료까지 안내하는 상용 서비스는 찾지 못했지만, 관련 연구는 있다.

| VizLens(2016)·[StateLens(2019)](https://arxiv.org/abs/1908.07144) (연구) | 휴대폰 카메라로 시각장애인의 손가락을 버튼까지 안내한다. StateLens는 결제 단말기·발권기처럼 화면이 바뀌는 터치스크린을 대상으로 한다. | 기기의 화면 상태도를 만들어 지금 어느 화면인지 추적하는 구조 | 기기마다 화면을 미리 라벨링해야 한다. |

| [Qwen2.5-VL](https://qwenlm.github.io/blog/qwen2.5-vl/) (기술) | 알리바바의 공개 비전-언어 모델(2025년 1월, 3B·7B·72B). 이미지 속 사물 위치를 JSON 좌표로 내고, 컴퓨터·휴대폰 화면을 조작하는 에이전트 기능이 있다. | 버튼 좌표를 JSON으로 받는 출력 형식, 화면 조작 에이전트 구조 | 화면 캡처가 아닌 **휴대폰으로 찍은 실제 사진**(기울기, 반사, 흐림)에 적용하고 성능을 측정한다. |

**차별점**: VizLens·StateLens·Kong 외 연구의 사전 등록 과정을 비전-언어 모델로 없애고, GuideMe의 VLM 안내를 카메라로 보는 실제 키오스크로 확장한다.

### 가져올 기능·구조·디자인

- **기능**: 촬영 후 대화로 이어가기(Be My AI), 답변마다 "맞았어요/틀렸어요" 피드백(Lookout), 연습 앱의 단계별 진행 표시
- **구조**
  - AI가 확신이 낮으면 다시 찍기나 후보 두 개 제시로 넘기는 대비책(Be My Eyes의 사람 연결에서 착안)
  - 버튼 좌표는 JSON으로 받아 서버에서 검증(Qwen2.5-VL)
  - 화면이 바뀔 때만 AI를 호출하는 방식(StateLens의 화면 상태 추적에서 착안)
- **디자인**
  - 한 화면에 한 가지 일만, 큰 글씨와 큰 버튼, 촬영 가이드 테두리와 소리 안내(Seeing AI)
  - 다음에 누를 곳을 기기 위에 직접 겹쳐 표시(Kong 외 AR 안내)
  - 대상 버튼만 남기고 주변을 어둡게 하는 강조 방식(GuideMe)
