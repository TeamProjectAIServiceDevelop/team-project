# 키오스크 길잡이 구현계획서 (Claude API 버전)

2026-11-04 · 이동건, 정윤서

[8조_구현계획.md](8조_구현계획.md)는 Ollama + Qwen2.5-VL을 직접 띄워 쓰는 계획이다. 이 문서는 **AI 부분을 Claude API로 바꿔 구현할 때** 무엇이 달라지는지 정리한다. 웹 화면(실시간 카메라, 자동 장면 선택, 빨간 상자, 음성 안내, 피드백 저장)은 그대로 두고, 바뀌는 곳만 적는다.

1장은 Sprint 2(11~12주) MVP, 2장은 Sprint 3 이후 완성본이다.

## 0. 무엇이 바뀌나 (요약)

| 항목 | 기존 (Qwen) | Claude 버전 |
| --- | --- | --- |
| AI 모델 | Qwen2.5-VL 3B (Ollama) | Claude Opus 5.5 (`claude-opus-5-5`) 기본, 측정용으로 Sonnet 5.5·Haiku 5.5 비교 |
| AI 서버 | 팀원 PC의 GPU + Cloudflare Tunnel | 필요 없음. Vercel 서버 함수에서 Anthropic API를 바로 호출 |
| 호출 코드 | `lib/ollama.ts` (`fetch`로 `/api/chat`) | `lib/claude.ts` (공식 SDK `@anthropic-ai/sdk`) |
| 출력 형식 강제 | Ollama `format` | 구조화 출력 `output_config.format` (JSON 스키마) |
| 응답 다양성 고정 | `temperature: 0` | 쓰지 않음(최신 모델은 `temperature`를 거절). 대신 `effort`로 생각 깊이 조절 |
| 비용 | 전기료뿐 | 호출당 과금 (아래 비용 추정 참고) |
| 서버가 꺼질 위험 | 높음 (PC·Tunnel 의존) | 낮음 (API 키만 있으면 됨) |
| LoRA 파인튜닝 | 가능 | 불가능. 프롬프트·예시(few-shot)·OCR 결합으로 대신함 |
| 개인정보 | 사진이 팀 PC 밖으로 안 나감 | 분석 장면이 Anthropic 서버로 전송됨 → 동의 안내 필요 |

**핵심 효과**: 기존 계획에서 가장 큰 남은 일이던 **A1(AI 서버 Tunnel 공개)이 API 키 발급과 환경변수 설정으로 줄어든다.** 대신 비용 관리와 개인정보 안내가 새 일로 생긴다.

## 1. MVP 구현 계획 (Sprint 2)

### 완료 기준 (시연 시나리오)

기존과 같다. 실제 매장 키오스크 앞에서 "아이스 아메리카노 한 잔 포장"을 말하고 시작하기를 누른 뒤 휴대폰을 비추면, 커피 → 아메리카노 → 아이스 → 포장 → 결제하기까지 버튼 표시와 음성 안내가 이어지고 완료 화면이 나온다. 정확도 1차 결과에는 **Claude 모델 세 가지의 비교표**가 들어간다.

### 웹과 AI의 접점: 그대로 유지

[lib/guide.ts](../lib/guide.ts)의 요청·응답 형식(`GuideRequest`, `Guide`, `MenuRequest`, `Menu`)은 바꾸지 않는다. 웹 쪽 코드(`app/kiosk-guide.tsx`, `app/live-camera.ts` 등)는 손대지 않는다. 바뀌는 것은 서버 안에서 모델을 부르는 부분뿐이다.

```
휴대폰(웹) ──/api/guide, /api/menu──▶ Vercel 서버 함수 ──SDK──▶ Anthropic API
                (형식 그대로)              lib/claude.ts            Claude Opus 5.5
```

### 코드 변경 계획

| 파일 | 변경 내용 |
| --- | --- |
| `package.json` | `npm install @anthropic-ai/sdk` |
| `lib/claude.ts` (새 파일) | `lib/ollama.ts`와 같은 모양의 `chat(system, user, image, schema)` 함수. SDK 클라이언트를 만들고 `client.messages.create`를 부른다. 실패하면 기존과 같은 `AiError`(503/502)를 던진다. |
| `lib/guide.ts` | ① `buildMessages`·`buildMenuMessages`가 Ollama 형식(`images: [...]`) 대신 Claude 형식(이미지 블록 + 텍스트 블록)을 만들도록 수정. ② `guideSchema`·`menuSchema`에 `additionalProperties: false`를 더함(구조화 출력 요구 사항). ③ 확신도 `confidence` 항목 추가(A3). `parseGuide`·`parseMenu`의 검증 로직은 그대로 둔다. |
| `app/api/guide/route.ts`, `app/api/menu/route.ts` | `import { chat } from "@/lib/ollama"`를 `@/lib/claude`로 바꾸거나, `AI_PROVIDER` 값에 따라 고르는 작은 함수를 거친다. 목업 모드는 그대로. |
| `.env.example` | `ANTHROPIC_API_KEY`, `CLAUDE_MODEL`(기본 `claude-opus-5-5`), `CLAUDE_EFFORT`(기본 `low`), `AI_PROVIDER`(`claude` / `ollama`) 추가 |

호출 모양(설명용 초안, 구현 때 SDK 문서로 확인):

```ts
const res = await client.messages.create({
  model: process.env.CLAUDE_MODEL ?? "claude-opus-5-5",
  max_tokens: 2000,
  output_config: { effort: "low", format: { type: "json_schema", schema: guideSchema } },
  system,                                   // 지금 buildMessages의 system 문구 그대로
  messages: [{ role: "user", content: [
    { type: "image", source: { type: "base64", media_type: "image/jpeg", data: req.image } },
    { type: "text", text: user },            // 목표, 누른 버튼, 질문
  ]}],
});
```

### 모델과 설정 결정

- **기본 모델은 Claude Opus 5.5**로 한다. 화면 속 작은 버튼 글자를 읽고 위치를 맞히는 일이라 정확도를 먼저 본다.
- 실시간 안내라 응답 시간이 중요하므로 **`effort: "low"`** 로 시작한다. Opus 5.5는 생각(thinking)을 끌 수 없고, 기본 effort가 `medium`이라 명시해서 낮춘다.
- `stop_reason`이 `refusal`이면 형식 오류와 똑같이 "다시 비춰 주세요"로 처리한다. 서버 측 대체 모델(`fallbacks: "default"`)을 켜 두어 거절 시 자동으로 다른 모델이 답하게 한다.
- 모델 이름은 환경변수 `CLAUDE_MODEL` 하나로 바꿀 수 있게 하고, A6 측정에서 **Opus 5.5 / Sonnet 5.5 / Haiku 5.5**를 같은 평가 데이터로 비교해 시연용 모델을 정한다. 속도·비용이 목표에 못 미치면 측정 결과를 근거로 바꾼다.

### 좌표 처리 주의점

Claude는 긴 변이 너무 큰 사진을 내부에서 줄여서 본다. 그러면 모델이 말한 픽셀 좌표가 우리가 보낸 사진 크기와 어긋날 수 있다. 그래서:

- 웹에서 AI로 보내는 장면을 **긴 변 1,568픽셀 이하**(실제로는 1,024픽셀 정도)로 줄여 보낸다. 지금 `app/frame.ts`의 축소 크기를 확인하고 필요하면 맞춘다.
- `width`, `height`는 줄인 뒤의 크기를 보내고, 프롬프트에도 그 크기를 적는다(지금 방식 그대로).
- A4 예시 10장으로 상자가 버튼 위에 제대로 겹치는지 먼저 눈으로 확인한다.

### 비용 추정

사진 1장(약 1,024×768)은 약 1,000토큰, 프롬프트·기록이 약 500토큰, 출력(생각 포함)이 약 300~600토큰이라고 잡으면:

| 모델 | 입력/출력 가격 (100만 토큰당) | 호출 1회 | 주문 1회(호출 10회) | 시연·측정 전체(약 2,000회) |
| --- | --- | --- | --- | --- |
| Opus 5.5 | $4 / $20 | 약 $0.01~0.02 | 약 $0.1~0.2 | 약 $20~40 |
| Sonnet 5.5 | $2 / $10 | 약 $0.005~0.01 | 약 $0.05~0.1 | 약 $10~20 |
| Haiku 5.5 | $0.10 / $0.50 | 약 $0.0005 이하 | 약 $0.005 | 약 $1 |

추정치이므로 첫 주에 응답의 `usage` 값을 기록해 실제 금액으로 고친다. 비용을 막는 장치:

- 자동 장면 선택(화면이 바뀌고 휴대폰이 멈췄을 때만 전송)은 그대로 두어 호출 수를 줄인다.
- Anthropic 콘솔에서 **월 사용 한도**를 정해 둔다.
- 배포 주소가 공개되므로 `/api/guide`, `/api/menu`에 간단한 요청 수 제한(같은 IP 1분당 N회)을 둔다.

### 구현할 기능 (기존 표에서 바뀌는 행만)

| 기능 | 바뀌는 점 | 담당 |
| --- | --- | --- |
| 다음 버튼 판단 | Qwen2.5-VL 대신 Claude가 같은 JSON을 낸다. 구조화 출력으로 형식 오류가 크게 줄 것으로 예상하지만, `parseGuide` 검증은 그대로 둔다. | 이동건 |
| 목표 입력(메뉴 읽기) | Claude로 메뉴 이름·가격을 읽는다. 한글 메뉴 글자 인식이 좋아질 것으로 예상, 실제 메뉴 사진으로 확인. | 이동건 |
| 응답 검증·재분석 | `refusal`, 시간 초과, 요청 수 제한(429) 처리를 더한다. SDK가 일시 오류는 자동으로 2번 다시 시도한다. | 이동건·정윤서 |
| 배포 | Tunnel이 빠진다. Vercel 환경변수에 `ANTHROPIC_API_KEY`만 넣으면 실제 안내가 된다. 서버 함수 실행 시간 제한이 응답 시간보다 넉넉한지 확인한다. | 정윤서 |
| 피드백 저장 | 저장 정책은 같다(사진 저장 안 함). 단 **분석 장면이 외부 AI 서비스로 전송된다는 안내**를 시작 화면이나 동의 절차에 넣는다. | 정윤서 |

**정윤서 · 웹 (`feat/web`)** — W1~W10은 그대로. 바뀌는 것만:

| # | 작업 | 완료 기준 |
| --- | --- | --- |

| 주 | 웹 | AI | 공동 |
| --- | --- | --- | --- |

### 리스크 관리 계획 (바뀌거나 새로 생긴 위험)

기존 표에서 "AI 서버를 준비하지 못하거나 시연 때 꺼짐"은 위험이 크게 줄어 아래 "API 장애"로 바꾼다. 나머지 위험(실시간 인식 불안정, 휴대폰·브라우저 차이, 라벨링 지연, 일정 지연)은 그대로다.

| 위험 | 가능성 | 영향 | 신호 | 대응 | 담당 |
| --- | --- | --- | --- | --- | --- |
| 응답이 느림(5초 초과) | 중간 | 큼 | 화면 변화 후 새 안내까지 평균 5초 초과 | effort `low` 유지, 장면 축소, `max_tokens` 적정화, Sonnet 5.5·Haiku 5.5와 비교 측정 후 모델 교체 | 이동건 |
| 비용 초과 | 중간 | 중간 | 콘솔의 하루 사용액이 예산의 1/10을 넘음 | 월 한도 설정, 요청 수 제한, 자동 장면 선택 기준 강화, 측정은 저렴한 모델부터 | 이동건 |
| API 키 유출 | 낮음 | 큼 | 깃허브나 클라이언트 코드에서 키 발견, 모르는 사용량 증가 | 키는 Vercel 환경변수에만, `.env.local`은 커밋 금지(이미 `.gitignore`), 서버 함수에서만 호출, 의심되면 즉시 키 폐기·재발급 | 공동 |
| API 장애·요청 수 제한(429) | 낮음 | 큼 | 시연 전날 점검에서 오류, 429 응답 반복 | SDK 자동 재시도, `AI_PROVIDER=ollama`(기존 경로)나 목업 모드로 전환, 시연 영상 준비 | 이동건 |
| 좌표가 어긋남 | 중간 | 큼 | 예시 10장에서 상자가 버튼 옆에 그려짐 | 보내는 장면 크기 고정, 프롬프트에 크기 명시, 그래도 어긋나면 비율(0~1) 좌표로 받도록 스키마 변경 | 이동건 |
| 외부 전송에 대한 개인정보 우려 | 중간 | 중간 | 사용자·평가자가 사진 전송을 문제 삼음 | 동의 화면에 외부 AI 전송 안내, 사진은 저장하지 않음, 얼굴·카드가 보이면 촬영하지 않도록 안내 | 정윤서 |
| 거절(refusal) 응답 | 낮음 | 작음 | `stop_reason: "refusal"`이 기록에 나타남 | 서버 측 대체 모델 사용, 실패하면 "다시 비춰 주세요"로 처리 | 이동건 |

### 실행 방법

```bash
npm install @anthropic-ai/sdk
cp .env.example .env.local     # ANTHROPIC_API_KEY, CLAUDE_MODEL, AI_PROVIDER=claude, DATABASE_URL 채우기
npm run dev                    # AI 없이 화면만 볼 때: KIOSK_AI_MOCK=1
```

- 휴대폰 카메라는 HTTPS에서만 열리므로 실기기 테스트는 Vercel 배포 주소로 한다. Tunnel은 더 이상 필요 없다.

## 2. 완성본 구현 계획 (Sprint 3 이후까지)

안내 경험(버튼을 따라가는 상자, 강조, 손가락 확인, 방향 안내, 메뉴 읽어 주기, 안내 중 대화, 다국어, 연습, 맞춤 설정)은 기존 계획과 같다. AI·성능 부분만 다음처럼 바뀐다.

| 항목 | 기존 | Claude 버전 |
| --- | --- | --- |
| 프롬프트 개선 | 2단계 질의, few-shot, 이미지 보정 | 같음. Claude는 긴 지시와 예시 사진을 잘 따르므로 few-shot 예시 사진을 시스템 프롬프트에 넣고 **프롬프트 캐싱**으로 반복 비용을 줄인다. |
| LoRA 파인튜닝 | 수집 데이터로 학습 | **하지 않는다.** 대신 실패 사례를 few-shot 예시와 프롬프트 규칙으로 되돌리는 방식으로 개선하고, 개선 전후를 같은 평가 데이터로 비교한다. |
| 모델 비교 실험 | Qwen 3B, 상용 API | Claude 세 모델 × effort 단계 비교. 필요하면 기존 Qwen 경로(`AI_PROVIDER=ollama`)도 같은 표에 넣어 "로컬 모델 vs Claude"를 보여 준다. |
| OCR 결합 | 위치 정확도가 낮을 때 시도 | 같음 |
| 같은 화면 캐시 | 호출 수 5~10회로 | 같음. 비용과 직접 이어지므로 우선순위를 올린다. |
| 다국어 안내 | 영어부터 | Claude는 다국어 출력이 자연스러워 영어·중국어·일본어를 함께 진행할 수 있다. 프롬프트의 `answerLang`만 늘린다. |
| 안내 중 대화 | 화면을 보고 답하기 | Claude에 지금 장면과 질문을 함께 보내 답을 받는다. 같은 `lib/claude.ts`를 재사용한다. |

### 도전 목표

| 지표 | MVP 목표 | 완성본 도전 목표 |
| --- | --- | --- |
| 버튼 안내 정확도 | 70% | 85% |
| 위치 정확도 | 60% | 75% |
| 화면 변화 후 새 안내까지 | 5초 | 3초 |
| 주문 1회당 AI 호출 | 측정만 | 10회 이하 |
| 주문 1회당 AI 비용 (새) | 측정만 | 시연 모델 기준 100원 이하 |

## 3. 결정이 필요한 것

1. **Claude 버전으로 갈지, 기존 Qwen 계획을 유지하고 Claude를 대체 경로로만 둘지.** Claude 버전은 일정 위험(AI 서버)이 줄고, 대신 비용과 "직접 모델을 다뤘다"는 기술 요소(LoRA)가 빠진다.
2. **API 비용을 누가 어떻게 낼지** (학교 지원, 팀 부담, 무료 크레딧).
3. **시연 모델** — A6 측정 결과로 정한다.
