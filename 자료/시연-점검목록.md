# 시연 점검 목록

2026-11-04 · 이동건

시연 전날과 당일 아침에 위에서부터 차례로 확인한다. 이번에 직접 겪은 문제(3B 중단, 임시 주소 변경, 모델 첫 응답 지연, 사진 크기에 따른 좌표 어긋남)를 반영했다.

## 1. 시연 전날

### AI 서버 PC (3060)

- [ ] 윈도우 절전·화면 끄기·덮개 닫기 동작을 **끔**으로 바꿨다. 절전에 들어가면 Tunnel이 끊긴다.
- [ ] 전원 어댑터를 꽂았다. 시연 도중 배터리가 닳으면 서버가 꺼진다.
- [ ] 모델이 받아져 있다.
  ```bash
  ollama list
  ```
  `qwen2.5vl:7b`가 보여야 한다. 3B는 이 PC의 Ollama(0.40.12)에서 구조화 출력이 중간에 깨져서 쓰지 않는다.
- [ ] GPU를 쓰고 있다. 모델을 한 번 부른 뒤 아래를 실행해 `PROCESSOR`가 `100% GPU`인지 본다. CPU로 돌면 매우 느리다.
  ```bash
  ollama ps
  ```
- [ ] 다른 GPU 프로그램(게임, 영상 편집, 브라우저 하드웨어 가속)을 껐다.

### Tunnel

- [ ] Tunnel을 켰다.
  ```bash
  cloudflared tunnel --url http://localhost:11434 --http-host-header="localhost:11434"
  ```
  출력에 나오는 `https://….trycloudflare.com` 주소를 적어 둔다. **다시 켜면 주소가 바뀐다.**
- [ ] 바깥에서 닿는지 확인했다. 목록에 모델 이름이 나오면 정상이다.
  ```bash
  curl https://<주소>/api/tags
  ```
- [ ] Vercel 환경변수를 새 주소로 바꾸고 **다시 배포**했다.
  ```
  OLLAMA_URL=<Tunnel 주소>
  OLLAMA_MODEL=qwen2.5vl:7b
  KIOSK_AI_MOCK=0
  ```
- [ ] 이 주소를 팀 밖에 공개하지 않았다. 주소를 아는 사람은 누구나 우리 Ollama를 쓸 수 있다.

### 배포 앱

- [ ] 휴대폰에서 배포 주소를 열어 카메라 권한이 허용된다(HTTPS에서만 열린다).
- [ ] **워밍업**: 모델이 메모리에 올라가는 첫 요청은 10초 가까이 걸린다. 시연 직전에 앱으로 아무 화면이나 한 번 분석시켜 둔다. 한 번 올라간 모델은 약 5분 쓰지 않으면 내려가므로, 시연 직전에 다시 한 번 한다.
- [ ] 평가 스크립트로 점수를 확인했다. 평소 값(버튼 93.8%, 위치 87.5%, 평균 약 2초)과 크게 다르면 뭔가 바뀐 것이다.
  ```bash
  npm run eval -- --data eval/data/mega --name 시연전 --pixels 1100000
  ```

### 보내는 사진 크기

- [ ] 앱이 AI에 보내는 사진이 **약 110만 픽셀**이다. 작게 보내면 모델이 낸 좌표가 어긋나 빨간 상자가 엉뚱한 곳에 그려진다(긴 변 1024로 줄이면 위치 정확도 0%였다). `app/frame.ts`를 확인한다.

## 2. 대비책 (하나라도 준비돼 있어야 한다)

문제가 생기면 위에서부터 쓴다.

| 상황 | 대비책 |
| --- | --- |
| Tunnel 주소가 바뀌거나 끊김 | Tunnel을 다시 켜고 Vercel `OLLAMA_URL`을 고쳐 다시 배포한다. 시연 전에 한 번 연습해 시간을 잰다. |
| 서버 PC가 꺼지거나 모델이 깨짐 | 모델을 내렸다 올린다(`ollama stop qwen2.5vl:7b` 후 다시 요청). 안 되면 PC를 재시작한다. |
| AI 서버를 못 살림 | 상용 API로 환경변수만 바꿔 전환한다(준비되어 있어야 한다). |
| 화면 인식이 전부 실패 | `KIOSK_AI_MOCK=1` 목업 모드로 화면 흐름만 보여 준다. 목업은 정해진 3단계만 돌려주므로, 목업이라고 말하고 쓴다. |
| 위의 모두 실패 | 미리 녹화한 시연 영상으로 발표한다. |

- [ ] 대체용 시연 영상을 녹화해 두었다(주문 한 건이 끝까지 가는 장면).
- [ ] 상용 API로 전환하는 경로를 시험해 두었다.

## 3. 시연 장소

- [ ] 시연할 키오스크(또는 모니터에 띄운 키오스크 화면)에서 미리 한 번 끝까지 해 봤다.
- [ ] 같은 화면으로 안 되던 동작이 없었다. 반사가 심하면 각도를 바꾸거나 화면 밝기를 낮춘다.
- [ ] 매장 키오스크를 쓰려면 **촬영 허락**을 받았고, 얼굴·카드 정보·영수증이 찍히지 않는다.
- [ ] 발표장 Wi-Fi/데이터가 되는지 확인했다. 휴대폰은 Vercel 주소만 열면 되지만, 서버 PC는 인터넷이 되어야 Tunnel이 유지된다.
- [ ] 휴대폰은 최소 두 대(Android Chrome, iPhone Safari)에서 시험했다. 음성 인식이 안 되면 글자 입력으로 대체한다.

## 4. 당일 아침 (30분 전)

- [ ] 서버 PC 켜고 절전 설정 다시 확인
- [ ] Ollama 실행 중 (`ollama ps`)
- [ ] Tunnel 켜서 새 주소 확인 → Vercel 환경변수 수정 → 다시 배포 → 배포가 끝났는지 확인
- [ ] 휴대폰으로 배포 주소에서 한 번 끝까지 시험
- [ ] 워밍업 요청 한 번
- [ ] 대체 영상과 상용 API 키가 바로 꺼낼 수 있는 곳에 있다

## 5. 알려진 한계 (질문받을 때 답할 것)

- 모델이 흐린 화면에서는 정확도가 크게 떨어진다(약한 흐림에서 정답이 반 이하로 줄었다). 그래서 상자가 없을 때는 "화면이 잘 안 보여요. … 다시 비춰 주세요"라고 안내한다.
- 평가 데이터가 적고(16문항, 한 종류의 키오스크) 라벨을 팀원이 직접 붙인 것이라 숫자는 참고용이다.
- 시연 서버는 개인 PC와 임시 주소라서, 실제 서비스로 쓰려면 고정 서버가 필요하다.
