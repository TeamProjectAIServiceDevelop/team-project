| 방법 | 장점 | 위험 |
|---|---|---|
| 배포 주소 + **목업 모드** | 확실히 동작, 화면 흐름을 다 보여 줌 | 실제 AI 판단이 아님을 밝혀야 함 |

## 4. Qwen 모델 선정 과정

문서에 남아 있는 근거 (발표에서 이 순서로 풀면 "선정 과정"이 된다):

1. **필요한 능력**: 처음 보는 키오스크 사진을 이해하고 **버튼 위치를 좌표로** 내야 한다 → 텍스트 전용 모델은 안 됨, **비전-언어 모델(VLM)** 이 필요 (`팀플기획서-초안.md` "일반 Qwen은 텍스트만 이해하므로…")
2. **Qwen2.5-VL을 고른 이유**: 공개 모델(3B·7B·72B, 2025년 1월), 이미지 속 위치를 **JSON 좌표로 출력**, 화면 조작 에이전트 기능 (`아이디어-상세기술.md` 기술 표)
3. **로컬 vs 상용 API**: 로컬 모델로 비용을 줄이고 상용 API(GPT·Gemini 계열)는 안정성·비교용으로 둔다. VLM은 화면이 바뀔 때만 불러 호출 수를 줄인다 (`아이디어-상세기술.md` "저비용 운영 목표")
4. **크기(7B → 3B)**: 기획서는 7B 기본·부족하면 3B → 구현 가이드라인에서 **3B로 확정**. 이유 = GPU 메모리(RTX 3060 12GB): 3B는 QLoRA 여유, 7B는 QLoRA도 빠듯·LoRA(16비트) 불가 (`AI_구현_가이드라인.md` 4절 표)
5. ☐ 채울 것: 다른 후보와 실제로 비교해 본 것이 있으면(상용 API, Qwen3-VL 소형 등 — 문서에는 "후보, 확인 필요"까지만 있음)

## 5. 파인튜닝을 하는 이유 — 숫자로

**현재 수치** (`이동건-작업메모.md` 3절 — 49문항, Qwen2.5-VL **7B**, 프롬프트만)

| 지표 | 값 | 목표 |
|---|---|---|
| 버튼 이름 맞음 | 73.5% (36/49) | 70% |
| 위치 맞음 | **57.1% (28/49)** | 60% |
| 이름·위치 둘 다 맞음 | 약 53~55% | — |
| 응답 시간 | 평균 약 3초 | 5초 |

- **확신도가 믿기 어렵다**: `high`인데 틀린 것이 49문항 중 15개 → 확신도로 틀린 안내를 걸러 내기 어렵다
- 라벨은 한 종류 키오스크(메가엠지씨)에서 어려운 곳을 일부러 많이 넣은 것이라 실제보다 낮게 나올 수 있다 — **발표에서 같이 밝힌다**
- 16문항 때의 87.5%·81.3%는 쉬운 문항이 많아 낙관적이었으므로 **인용하지 않는다**(작업 메모)

**이유로 이어지는 논리** (기획서의 단계적 개발: 프롬프트 → few-shot·이미지 보정 → 그래도 부족하면 LoRA)
- 프롬프트만으로는 **위치 정확도가 목표(60%)에 못 미치고**, 확신도도 믿을 수 없다
- 실제로 쓸 모델은 **3B**(GPU 제약)인데, 7B로도 위치가 57%라면 3B는 더 낮을 가능성이 크다 → **작은 모델을 키오스크 데이터로 학습시켜 보완**한다 ☐ 3B 원본 수치가 있으면 넣기
- 방법: **LoRA / QLoRA** — 모델 전체가 아니라 작은 어댑터만 학습, 바뀌는 값이 전체의 1% 안팎이라 개인 GPU로 가능 (`AI_구현_가이드라인.md` 4절)
- 평가 계획: **학습에 쓰지 않은 매장** 사진으로 "3B 원본 / 3B + LoRA"(7B 원본은 참고)를 같은 표에 놓는다 → "작은 모델도 학습하면 큰 모델만큼 되나"를 본다
