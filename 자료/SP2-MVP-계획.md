# Sprint 2 MVP 구현 계획 (11~12주)

12주 평가 시연 목표: **찍기 버튼 없이 카메라로 키오스크를 비추면, 실시간 화면 위에 눌러야 할 버튼이 표시되고 음성으로 안내되며, 주문을 끝까지 마칠 수 있다.** (기획서 9.1 Sprint 2)

## 1. 시작 시점 상태 (첫 버전, master `da3456d`)

| 기능 | 상태 |
|---|---|

| 음성 입력(STT)·음성 안내(TTS), 한국어/영어 | ✅ |
| AI 서버 연결(Ollama + Qwen2.5-VL), 좌표 변환·검증 | ✅ (`lib/guide.ts`) |

| 실시간 카메라, 둘러보기, 피드백 저장, 확신도, 평가 스크립트 | ❌ → 이번 스프린트 |

## 2. MVP 범위 (기획서 9.2 기준)

- **필수**: 실시간 카메라 버튼 안내(문구 + 위치), 음성 입출력, Vercel 배포, 정확도 1차 측정
- **권장**: 둘러보기(목표 없이 시작), 피드백 저장, 확신도 판단
- **이번에 안 함**: LoRA 파인튜닝(Sprint 3), 개선 전후 비교(Sprint 3)
- **대체**: 찍기 버튼 방식(첫 버전)은 앱에서 뺐다(실시간 영상 안내만 남김). 실시간 인식이 불안정하면 git 기록(`90aaaff`)에서 되살리거나 시연 영상으로 대신한다

## 4. 인터페이스 변경 (`lib/guide.ts`) — 두 사람이 함께 확인

1. **반영함**: `goal`이 빈 문자열이면 목표 없이 시작한 것. `isBrowsing()`으로 판단한다. 다음 단계 버튼(주문하기, 매장/포장 등)이 분명하면 그 버튼과 `box`를 내고, 메뉴처럼 골라야 하는 화면이면 `button: ""`, `box: []`로 선택지를 읽어 준다. 누른 버튼 기록(`history`)도 함께 보낸다.
2. **제안 (A3)**: 응답에 `confidence: "high" | "medium" | "low"` 추가. 웹은 `low`면 상자를 띄우지 않고 다음 장면을 다시 분석한다. 두 번 질의 비교는 응답 시간이 두 배가 되므로 1차 측정 결과를 보고 결정한다.

## 6. 실행 방법

```bash
cp .env.example .env.local     # OLLAMA_URL, OLLAMA_MODEL, DATABASE_URL 채우기
npm run dev                    # AI 없이 화면만 볼 때: .env.local에 KIOSK_AI_MOCK=1
```

- 피드백 저장 테이블: Neon 콘솔 SQL Editor에서 `db/schema.sql` 실행
- 휴대폰 카메라는 HTTPS에서만 열린다. 실기기 테스트는 Vercel 배포 주소나 Tunnel 주소로 한다.

## 7. 알려진 한계

- 화면 변화 기준값(`app/live-camera.ts`의 `MOVING`, `CHANGED`)은 추정치라 실제 매장에서 조정해야 한다.
- 가짜 응답 모드는 누른 버튼 기록이 실제 모델 응답에 따라 쌓이므로, 실시간 모드에서는 첫 단계 안내만 반복된다. 단계 진행 확인은 실제 모델로 한다.
