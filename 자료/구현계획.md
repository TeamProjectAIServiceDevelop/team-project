# 키오스크 길잡이 구현 계획

2026-10-28 · 이동건, 정윤서

## 1. MVP 구현 계획 (Sprint 2)

Sprint 2까지 **찍기 버튼 없이 카메라를 비추기만 하면, 실시간 화면 위 버튼 표시와 음성 안내를 받으며 주문을 끝까지 마치는 버전**을 만든다.

### 완료 기준 (시연 시나리오)

실제 매장 키오스크 앞에서 "아이스 아메리카노 한 잔 포장"을 말하고 휴대폰을 비추면, 커피 → 아메리카노 → 아이스 → 포장 → 결제하기까지 버튼 표시와 음성 안내가 이어지고 완료 화면이 나온다. 동시에 평가 데이터로 잰 정확도 1차 결과를 발표한다.

### 현재 상태 (첫 버전)

저장소에는 턴 방식 프로토타입이 있다. 목표 음성 입력(STT), 촬영·사진 업로드, Qwen2.5-VL(Ollama) 호출, JSON 응답 검증과 좌표의 비율 변환, 사진 위 빨간 상자, 음성 안내(TTS), "눌렀어요"로 이어가는 단계 기록, AI 없이 흐름을 보는 목업 모드까지 동작한다. MVP는 이 위에 **실시간 카메라, 자동 장면 선택, 확신도 판단, 피드백 저장, 배포, 정확도 측정**을 더한다.

### 구현할 기능

| 기능 | 설명 | 담당 | 우선순위 |
| --- | --- | --- | --- |
| 목표 입력 | 원하는 주문을 말로 입력(STT)하고 인식된 문장을 크게 보여 준다. 음성 인식이 안 되면 글자로 입력한다. | 정윤서 | 필수 |
| 실시간 카메라 화면 | 찍기 버튼 없이 후면 카메라 화면을 계속 보여 주고, 가이드 테두리와 "테두리 안에 들어오게 비춰 주세요" 음성을 낸다. | 정윤서 | 필수 |
| 자동 장면 선택 | 1초에 한 번 작게 줄인 프레임을 직전 장면과 비교해, 흔들림이 적고 화면이 바뀌었을 때만 한 장을 AI에 보낸다(Canvas 축소 이미지 비교). | 정윤서 | 필수 |
| 다음 버튼 판단 | Qwen2.5-VL이 목표·누른 버튼 기록·장면을 보고 화면 단계, 다음 버튼, 좌표, 확신도, 안내문, 완료 여부를 JSON으로 낸다. 응답 형식에 확신도 항목을 추가한다. | 이동건 | 필수 |
| 버튼 위치 표시 | 좌표를 0\~1 비율로 바꿔 실시간 카메라 화면 위에 빨간 상자와 "여기를 누르세요"를 그린다. 휴대폰이 크게 움직이면 상자를 숨기고 다시 분석한다. | 정윤서 | 필수 |
| 음성 안내 | 안내문을 TTS로 읽고, [다시 듣기]와 말하는 속도 조절을 제공한다. AI가 분석하는 동안 "화면을 확인하고 있어요"라고 알려 준다. | 정윤서 | 필수 |
| 응답 검증·재분석 | 형식·좌표 범위가 틀리거나 확신도가 낮으면 상자를 띄우지 않고 다음 장면으로 다시 분석한다. 계속 실패하면 "조금 더 가까이 비춰 주세요"로 안내한다. | 이동건·정윤서 | 필수 |
| 단계별 진행·완료 | 누른 버튼을 기억하고, 화면이 바뀌면 자동으로 다음 안내를 한다. 완료 화면에서는 누른 단계 목록과 "주문이 끝났어요"를 보여 준다. 결제 단계에서는 금액 확인을 안내한다. | 정윤서 | 필수 |
| 배포 | 웹은 Vercel(HTTPS, 휴대폰 카메라에 필요), AI 서버는 Ollama를 Cloudflare Tunnel로 연결한다. 상용 API 대체 경로를 환경변수 하나로 전환할 수 있게 한다. | 정윤서·이동건 | 필수 |
| 정확도 1차 측정 | 매장 10곳 이상 키오스크 사진 200장 이상에 정답 버튼을 라벨링하고, 평가 스크립트로 버튼 안내 정확도(목표 70%)·위치 정확도(목표 60%)·응답 시간(목표 5초)을 잰다. | 이동건 (수집·라벨링 공동) | 필수 |
| 피드백 저장 | 안내마다 [맞았어요] [틀렸어요]를 받아 동의한 경우에만 Neon Postgres에 저장한다. | 정윤서 | 권장 |

찍기 버튼 방식(첫 버전)은 지우지 않고 대체 경로로 남긴다. 실시간 인식이 불안정하면 이 방식으로 시연한다.

### 두 사람의 접점

웹과 AI는 [lib/guide.ts](../lib/guide.ts)의 요청·응답 형식으로만 만난다. MVP에서 바뀌는 점은 응답에 **확신도**를 더하는 것 하나다. 이 형식을 먼저 확정하고 각자 `feat/ai`, `feat/web` 브랜치에서 개발한 뒤 Pull Request로 합친다.

위험마다 언제 터졌다고 볼지 **신호**를 정해 두고, 신호가 보이면 바로 대응으로 넘어간다. 매주 한 번 두 사람이 이 표를 보고 상태를 고친다.

## 2. 완성본 구현 계획 (Sprint 3 이후까지)

완성본은 **휴대폰을 흔들어도 상자가 버튼에 붙어 따라가고, 손가락이 버튼에 닿으면 알아서 다음 단계로 넘어가는 길잡이**다. 여기에 모델 개선과 비교 실험, 둘러보기·연습·다국어 기능을 더해 "처음 보는 키오스크도 혼자 주문"을 수치로 보여 준다.

### 안내 경험

| 기능 | 설명 |
| --- | --- |
| 버튼을 따라가는 상자 | OpenCV.js 특징점 추적으로 휴대폰이 움직여도 빨간 상자가 버튼 위에 그대로 붙어 있다. AI는 화면이 바뀔 때만 부르고, 매 프레임은 휴대폰이 처리한다. |
| 대상 버튼만 남기는 강조 | 화면 전체를 어둡게 덮고 눌러야 할 버튼만 밝게 뚫어 보인다(GuideMe 방식). |
| 손가락 확인과 자동 진행 | MediaPipe 손 추적으로 손가락이 목표 버튼에 닿은 뒤 화면이 바뀌면 다음 단계로 넘어간다. 다른 버튼에 손이 가면 "그 버튼이 아니에요"라고 미리 알려 준다. |
| 비추는 방향 음성 안내 | 화면이 잘리거나 흐리면 "조금 더 왼쪽으로", "조금 더 가까이"처럼 소리로 알려 준다. 저시력 사용자도 혼자 비출 수 있다. |
| 둘러보기 모드 | 목표 없이 시작하면 화면의 메뉴와 가격을 읽어 준다. "이걸로 할게요"라고 말하면 바로 주문 안내로 넘어간다. |
| 안내 중 대화 | "얼음 적게 돼요?", "포장 말고 매장으로 바꿀게요"처럼 말하면 화면을 보고 답하거나 목표를 고친다. |
| 다국어 안내 | 영어를 먼저 완성하고 중국어·일본어로 넓힌다. 한국어 키오스크를 사용자의 언어로 설명한다. |
| 집에서 미리 연습 | 매장 키오스크 사진으로 집에서 같은 안내를 받으며 연습해, 매장에서 뒷사람 눈치 부담을 줄인다. |
| 나에게 맞춘 설정 | 글씨 크기, 고대비 화면, 말하는 속도를 기억한다. 홈 화면에 추가하는 웹 앱(PWA)과 QR코드로 바로 연다. |

### AI와 성능

| 항목 | 설명 |
| --- | --- |
| 프롬프트 개선 | 화면 단계 판단 → 버튼 선택 2단계 질의, few-shot 예시, 이미지 보정(회전·밝기) |
| LoRA 파인튜닝 | 수집한 키오스크 데이터로 학습하고, 학습에 쓰지 않은 매장으로 전후 성능을 비교한다. |
| 모델 비교 실험 | Qwen2.5-VL 7B·3B, 상용 API(GPT·Gemini 계열), 더 최신 소형 VL 모델(확인 필요)을 같은 평가 데이터로 비교해 정확도·응답 시간·비용 표를 만든다. |
| 같은 화면 캐시 | 방금 본 화면과 같으면 AI를 다시 부르지 않고 결과를 재사용해 주문 1회당 호출을 5\~10회로 줄인다. |
| 피드백으로 개선 | [틀렸어요]가 눌린 장면을 모아 실패 유형을 분류하고, 프롬프트와 학습 데이터에 되돌린다. 결과는 간단한 관리 화면에서 본다. |

### 도전 목표

| 지표 | MVP 목표 | 완성본 도전 목표 |
| --- | --- | --- |
| 버튼 안내 정확도 | 70% | 85% |
| 위치 정확도 | 60% | 75% |
| 화면 변화 후 새 안내까지 | 5초 | 3초 |

### 더 나아갈 수 있다면

- **다른 무인기기**: 무인민원발급기, 병원 접수기, 주차 정산기에서도 같은 방식으로 안내해 본다.
- **휴대폰 안의 작은 모델**: 화면 단계 판단처럼 가벼운 일은 휴대폰에서 처리해 서버 왕복을 줄인다.
- **키오스크 종류 기억**: 한 번 안내한 키오스크의 화면 구조를 저장해, 다음 사용자에게 더 빠르고 정확하게 안내한다.
- **공개 데이터셋**: 개인정보를 지운 키오스크 화면·정답 버튼 데이터를 접근성 연구용으로 정리한다.
