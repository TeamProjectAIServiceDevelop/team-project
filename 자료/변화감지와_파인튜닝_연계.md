# 변화 감지 기반 AI 호출과 LoRA 파인튜닝 연계

## 1. 용어

화면에 변화가 있을 때만 AI를 부르는 방식은 아래 이름으로 부른다.

- **변화 감지 기반 이벤트 트리거 (Change Detection–Triggered Processing)**, **이벤트 기반 추론 (Event-driven Inference)**
- **Frame Differencing (프레임 차분)**: 이전 프레임과 현재 프레임의 픽셀 차이로 변화를 감지한다. 우리 프로젝트가 쓰는 방식이다.
- **2단계(cascade) 파이프라인 / 게이팅(gating) 구조**: 가벼운 판단이 먼저 걸러내고, 무거운 모델(VLM)은 필요할 때만 부른다.
- 관련 용어: Scene Change Detection, Motion Detection, Keyframe Extraction, Frame Skipping

발표 문장 예: "프레임 차분 기반 변화 감지로 장면이 바뀌었을 때만 AI를 호출하는 게이팅 구조"

## 2. 왜 필요한가

- Qwen2.5-VL을 Ollama로 로컬에서 돌리면 API 요금은 없다. 대신 **GPU 연산량과 지연 시간**이 비용이다.
- 영상은 초당 30프레임이고, VLM 한 번 추론에는 수백 ms에서 수 초가 걸린다. 모든 프레임을 넣을 수 없다.
- 화면이 그대로인 구간을 다시 분석하면 같은 결과를 반복 계산할 뿐이다.

## 3. 현재 구현 (이미 들어가 있음)

```
[휴대폰 브라우저] 카메라 영상
    ↓ 0.5초마다
[변화 감지] app/frame.ts, app/live-camera.ts   ← 가볍다 (수 ms)
    ↓ 멈춰 있고 + 마지막 분석 장면과 달라졌을 때만
[서버] /api/guide → lib/ollama.ts → Qwen2.5-VL 3B   ← 무겁다
    ↓
[화면] 버튼 상자 1·2·3 표시 + 음성 안내
```

- 휴대폰 웹앱이라 영상이 서버로 오지 않는다. 그래서 OpenCV 대신 **브라우저 canvas**로 변화를 감지한다.
- `signature()`: 화면을 32×18 흑백으로 줄인다. `difference()`: 평균 밝기 차이(0~255)를 구한다.
- `live-camera.ts`의 판단 기준:

| 상수 | 값 | 의미 |
|---|---|---|
| `CHECK_MS` | 500 | 비교 간격 |
| `MOVING` | 10 | 직전 비교보다 이만큼 달라지면 휴대폰이 움직이는 중 ("멈춰 주세요" 안내) |
| `STEADY_CHECKS` | 2 | 이만큼 연속으로 멈춰 있어야 보낸다 (안정화 대기) |
| `CHANGED` | 14 | 마지막으로 분석한 장면보다 이만큼 달라져야 새 장면 |

- 앞 요청이 끝나기 전(`busy`)에는 새 장면을 보내지 않는다 (중복 호출 방지).
- 오류가 난 뒤나 처음 시작할 때는 `rescan()`으로 같은 화면도 다시 보낸다.

### 개선 후보

- 임계값을 실제 매장에서 로그를 찍어 보며 다시 맞춘다.
- 평균 밝기 차이는 반사나 깜빡임에 반응할 수 있다. 화면을 격자로 나눠 "바뀐 칸의 비율"로 판단하면 더 안정적이다.

## 4. LoRA 파인튜닝과의 관계

변화 감지와 파인튜닝은 서로 독립적이다. 파인튜닝이 끝나면 `/api/guide` 뒤의 모델만 바꾸면 된다(`OLLAMA_MODEL`). 다만 둘이 맞닿는 지점은 아래와 같다.

1. **학습 사진 크기를 앱과 맞춘다.** 앱은 28의 배수이면서 약 98만 픽셀(예: 840×1176)로 보낸다(`app/frame.ts`). 학습 데이터 크기가 다르면 상자 좌표가 어긋난다.
2. **실제 앱이 보낸 프레임을 학습 데이터로 쓴다.** 변화 감지를 통과한 사진은 휴대폰이 멈춘 상태의 실제 장면이라 사용 환경과 가장 비슷하다.
3. **출력 형식을 유지한다.** 1단계는 `guideSchema` JSON, 2단계는 `bbox_2d` 형식으로 정답을 만들어야 `lib/guide.ts` 파서를 그대로 쓴다.
4. **GGUF 변환부터 확인한다.** 비전 모델은 LoRA를 합친 뒤 Ollama용 GGUF 변환이 막힐 수 있다(`AI_구현_가이드라인.md` 4장). 막히면 vLLM(OpenAI 호환 API)으로 띄우고, `lib/ollama.ts` 옆에 호출 파일을 하나 더 만들어 환경변수로 고른다. 이 작업은 `feat/ai` 브랜치에서 한다.

## 5. 왜 영상이 아니라 사진(JPEG)을 보내나

- 화면에는 실시간 영상이 보이지만, 서버로는 **변화 감지가 고른 한 장면만 JPEG 사진으로** 보낸다(`captureFrame()`).
- Qwen2.5-VL의 영상 입력도 결국 영상을 여러 장의 사진으로 잘라 넣는 방식이다. 키오스크 화면은 한 장으로 판단할 수 있으니 여러 장을 넣으면 연산만 늘어난다.
- 영상을 계속 올리면 휴대폰 데이터와 서버 부담이 크다. 사진은 한 번에 수백 KB 수준이다.
- 버튼 상자를 **AI가 본 바로 그 사진 위에** 그려야 좌표가 정확히 겹친다. 영상 위에 그리면 그사이 휴대폰이 움직여 어긋난다.
- 목표 메뉴를 고르는 단계(`/api/menu`)만은 자동 감지 대신 사용자가 "찍기" 버튼을 눌러 사진을 보낸다. 메뉴 화면 전체가 들어왔는지 사용자가 직접 정하는 게 정확하기 때문이다.
