키오스크 길잡이

어떤 키오스크든 카메라로 비추면 음성으로 주문을 도와주는 AI 서비스

요약

1) 서비스 개요
휴대폰 카메라로 키오스크 화면을 비추면, AI가 눌러야 할 버튼을 화면에 표시하고 음성으로 안내하는 모바일 웹 서비스

2) 개발 배경
  (1) 키오스크마다 화면 구성이 다르고 단계가 많아 고령자·저시력자가 주문에 어려움을 겪음
  (2) 배리어프리 키오스크는 기기 교체가 필요하고, 연습 앱은 실제 매장 화면과 다름
   → 키오스크를 바꾸지 않고 사용자의 휴대폰만으로 해결

3) 사용 흐름
① 원하는 주문을 말로 입력 → ② 키오스크 화면 촬영 → ③ AI가 눌러야 할 버튼을 표시하고 음성 안내 → ④ 주문 완료까지 반복

4) 핵심 기술
  (1) 비전-언어 모델(Qwen2.5-VL): 처음 보는 키오스크 화면에서 버튼 위치를 찾음
  (2) 음성 인식·합성(STT/TTS): 말로 묻고 말로 안내
  (3) 단계적 개발: 프롬프트로 먼저 구현 → 정확도가 부족하면 LoRA 파인튜닝

5) 결과물 및 평가
  (1) Next.js 모바일 웹으로 개발해 Vercel에 배포
  (2) 학습 없이 프롬프트만으로 동작하는 것이 기본
  (3) 직접 수집한 키오스크 화면 200장 이상을 평가용으로 사용해 버튼 안내 정확도(목표 70% 이상), 주문 완료율, 응답 시간(목표 5초 이내) 측정

1. 개발 배경 및 필요성

1.1 배경
  1) 국내 키오스크는 2019년 18만 9,951대에서 2022년 45만 4,741대로 3년 사이 2.4배 증가, 같은 기간 요식업은 17배 증가(과학기술정보통신부, 이투데이)
  2) 키오스크는 매장마다 화면 구성이 다르고, 글씨가 작고, 단계가 많음
  3) 서울 고령층(55세 이상)의 59.6%가 키오스크 이용 중 어려움을 겪었고, 이용 경험률은 55~64세 79.1%, 65~74세 50.4%, 75세 이상 19.1%로 나이가 많을수록 급격히 낮아짐(서울디지털재단, 2023 서울시민 디지털역량실태조사)
  4) 장애인 키오스크 이용자의 불편 사항으로 "뒷사람 눈치가 보임"(54.0%), "버튼 위치 찾기나 메뉴 선택·이동의 어려움"(26.1%)이 꼽힘(보건복지부, 2024 장애인차별금지법 이행 실태조사)
  5) 한국은 2024년 12월 초고령사회에 진입, 65세 이상 1,024만 명으로 전체 인구의 20% → 도움이 필요한 사람은 계속 늘어남
  6) 고령자, 저시력 사용자는 주문을 포기하거나 다른 사람의 도움을 받아야 함 → 디지털 격차

1.3 차별점
  1) 키오스크가 아니라 사용자의 휴대폰 쪽에서 문제를 해결하므로 기존 키오스크에 바로 적용 가능
  2) 미리 등록된 화면이 아니라 처음 보는 키오스크 화면도 AI가 읽고 판단
  3) 안내 문구를 미리 코딩하는 방식으로는 불가능한 기능이므로 AI가 꼭 필요함

2. 개발 목표

2.1 목표
  1) 실제 매장의 키오스크 사진에서 사용자의 목표를 이루기 위해 다음에 눌러야 할 버튼을 찾아 안내
  2) 눌러야 할 버튼을 촬영 사진 위에 빨간 상자로 표시
  3) 말로 묻고 말로 듣는 음성 대화 지원
  4) 직접 구축한 데이터셋으로 안내 정확도를 수치로 측정하고 개선
  5) 앱 설치 없이 링크로 쓰는 모바일 웹으로 배포

7. 개발 방법론

7.1 모델 선택
  1) 일반 Qwen은 텍스트만 이해하므로, 화면 사진을 이해하는 비전-언어 모델 Qwen2.5-VL 사용
  2) 이미지 속 UI 요소의 위치를 좌표로 출력할 수 있어 버튼 위치 표시에 적합
  3) 공개 모델이라 로컬에서 직접 실행 가능 → 호출당 과금 없음
  4) 7B 모델을 기본으로 하고, GPU 메모리가 부족하면 3B 모델 사용

7.2 단계적 개발
[표] 아래 줄을 선택하고 '문자열을 표로' (탭으로 구분)
단계	방법	내용
1단계	프롬프트 (학습 없음)	사진, 목표, 출력 형식(JSON)을 주는 프롬프트를 설계해 전체 흐름을 먼저 완성
2단계	프롬프트 개선	화면 단계 판단 → 버튼 선택의 2단계 질의, 예시를 넣은 few-shot, 이미지 보정(회전, 밝기)
3단계	LoRA 파인튜닝 (필요 시)	1·2단계 정확도가 부족하면 수집 데이터로 학습하고 전후 성능 비교

7.3 출력 형식
{
  "화면단계": "메뉴 선택",
  "다음버튼": "커피",
  "위치설명": "화면 왼쪽 위 첫 번째 탭",
  "좌표": [120, 80, 260, 140],
  "확신도": "높음",
  "안내문": "왼쪽 위의 '커피' 탭을 누르세요.",
  "완료": false
}

  1) 좌표 변환: Qwen2.5-VL은 모델에 들어간(크기가 바뀐) 이미지 기준의 픽셀 좌표를 출력하므로, 웹 서버가 입력 이미지 크기로 나눠 0~1 비율 좌표로 바꾼 뒤 원본 사진 위에 그림
  2) 검증: 웹 서버가 JSON 형식과 좌표 범위를 검증하고, 실패하거나 버튼을 찾지 못하면(좌표가 비어 있음) "다시 찍어 주세요"로 안내
  3) 확신도 판단: 모델이 스스로 매긴 확신도가 "낮음"이거나, 같은 사진에 두 번 질의해 고른 버튼이 서로 다르면 확신이 낮다고 보고 다시 촬영을 요청
  4) 완료 판단: 주문 완료·영수증 출력 화면이면 "완료"를 true로 하고 ④ 완료 화면으로 이동

7.4 데이터
  1) 용도: 기본 방식(1·2단계)은 학습을 하지 않으므로, 수집한 데이터는 성능 평가용으로 사용
    (1) 정답이 붙은 사진에서 AI가 고른 버튼과 정답을 비교해 정확도 측정
    (2) 3단계 파인튜닝을 할 경우에만 일부를 학습용으로 추가 사용
  2) 수집: 학교 주변 카페, 패스트푸드점, 영화관 등 매장 10곳 이상에서 키오스크 화면 200장 이상 촬영(6~9주, 두 사람이 각자 매장 5곳 이상)
  3) 라벨링: 사진마다 목표와 정답 버튼(이름, 좌표) 표시, 한 사진에 여러 목표를 붙여 평가 문항 확대(Label Studio 등 사용)
  4) 분할(파인튜닝 시): 매장 단위로 학습용과 평가용을 나눠, 학습에 쓰지 않은 매장으로 처음 보는 키오스크 성능 확인
  5) 개인정보: 사람 얼굴과 결제 정보가 찍히지 않게 촬영, 촬영 전 매장에 허락을 구함
