키오스크 길잡이

어떤 키오스크든 카메라로 비추면 음성으로 주문을 도와주는 AI 서비스

요약

1) 서비스 개요
휴대폰 카메라로 키오스크 화면을 비추면, AI가 눌러야 할 버튼을 실시간 카메라 화면 위에 표시하고 음성으로 안내하는 모바일 웹 서비스

2) 개발 배경
  (1) 키오스크마다 화면 구성이 다르고 단계가 많아 고령자·저시력자가 주문에 어려움을 겪음
  (2) 배리어프리 키오스크는 기기 교체가 필요하고, 연습 앱은 실제 매장 화면과 다름
   → 키오스크를 바꾸지 않고 사용자의 휴대폰만으로 해결

3) 사용 흐름
① 원하는 주문을 말로 입력 → ② 카메라로 키오스크를 비춤(찍기 버튼 없음) → ③ AI가 실시간 화면 위에 눌러야 할 버튼을 표시하고 음성 안내 → ④ 버튼을 누르면 바뀐 화면을 자동으로 인식해 주문 완료까지 이어서 안내

4) 핵심 기술
  (1) 비전-언어 모델(Qwen2.5-VL): 처음 보는 키오스크에서 버튼 위치를 찾음
  (2) 음성 인식·합성(STT/TTS): 말로 묻고 말로 안내
  (3) 단계적 개발: 프롬프트로 먼저 구현 → 정확도가 부족하면 LoRA 파인튜닝
  (4) 실시간 카메라: 화면은 끊김 없이 보이고, AI 안내는 화면이 바뀔 때마다 몇 초 안에 갱신

5) 결과물 및 평가
  (1) Next.js 모바일 웹으로 개발해 Vercel에 배포
  (2) 직접 수집한 키오스크 사진 200장 이상과 영상 장면을 평가용으로 사용해 버튼 안내 정확도(목표 70% 이상), 응답 시간(화면이 바뀐 뒤 새 안내까지 목표 5초 이내) 측정

1. 개발 배경 및 필요성

1.1 배경
  1) 국내 키오스크는 2019년 18만 9,951대에서 2022년 45만 4,741대로 3년 만에 2.4배 늘었으며, 같은 기간 요식업 키오스크는 17배 증가했다(과학기술정보통신부, 이투데이).
  2) 그러나 키오스크는 매장마다 화면 구성이 다르고 글씨가 작으며 주문 단계가 많아, 처음 쓰는 사람이 이용하기 어렵다.
  3) 서울 시민의 키오스크 이용 경험률은 55~64세 79.1%에서 65~74세 50.4%, 75세 이상 19.1%로 65세 이후 급격히 낮아졌고, 55세 이상 고령층의 59.6%는 이용 중 어려움을 겪었다(서울디지털재단, 2023 서울시민 디지털역량실태조사).
  4) 장애인 키오스크 이용자는 불편 사항으로 "뒷사람 눈치가 보임"(54.0%)과 "버튼 위치 찾기나 메뉴 선택·이동의 어려움"(26.1%)을 꼽았다(보건복지부, 2024 장애인차별금지법 이행 실태조사).
  5) 한국은 2024년 12월 65세 이상 인구가 1,024만 명으로 전체의 20%가 되어 초고령사회에 진입했으므로, 도움이 필요한 사람은 앞으로 더 늘어날 것이다.
  6) 그 결과 고령자와 저시력 사용자는 주문을 포기하거나 다른 사람의 도움을 받아야 하며, 이는 디지털 격차로 이어진다.

1.2 기존 해결책의 한계
  1) 배리어프리 키오스크는 2026년 1월 28일부터 의무화되었지만, 기기를 교체해야 하므로 보급이 더디다(경기도 227대, 서울 552대 수준, 경인일보).
  2) 키오스크 교육·연습 앱은 가상 화면으로 연습하기 때문에, 화면 구성이 다른 실제 매장 키오스크에는 그대로 적용하기 어렵다.
  3) 직원의 도움은 무인 매장이나 바쁜 시간에는 받기 어렵다.

1.3 차별점
  1) 키오스크 길잡이는 키오스크가 아니라 사용자의 휴대폰에서 문제를 해결하므로, 이미 설치된 키오스크에 바로 적용할 수 있다.
  2) 미리 등록된 화면만 다루는 기존 연구와 달리, AI가 처음 보는 키오스크 화면도 실시간 카메라로 읽고 다음에 누를 버튼을 판단한다.
  3) 매장마다 다른 화면에 맞는 안내를 미리 만들어 둘 수는 없으므로, 이 기능에는 AI가 꼭 필요하다.

2. 개발 목표

2.1 목표
  1) 실제 매장의 키오스크를 비춘 카메라 화면에서 사용자의 목표를 이루기 위해 다음에 눌러야 할 버튼을 찾아 안내
  2) 눌러야 할 버튼을 실시간 카메라 화면 위에 빨간 상자로 표시하고, 화면이 바뀌면 찍기 버튼 없이 자동으로 다음 안내
  3) 말로 묻고 말로 듣는 음성 대화 지원
  4) 직접 구축한 데이터셋으로 안내 정확도를 수치로 측정하고 개선
  5) 앱 설치 없이 링크로 쓰는 모바일 웹으로 배포

3. 벤치마킹(또는 관련 연구)


3.1 유사 서비스
  1) Be My Eyes / Be My AI: 시각장애인이 찍은 사진을 GPT-4 기반 AI가 설명하고 질문에 답함(2023) → 보이는 것을 설명할 뿐, 주문 목표를 기억하고 다음 버튼을 고르지 않음
  2) ChatGPT·Gemini 실시간 카메라 대화: 카메라를 비추고 말로 물어볼 수 있음 → 목표·진행 단계를 기억하지 않고 버튼 위치를 표시하지 않음
  3) 해피트리 교육용 키오스크 체험 앱: 15종 가상 키오스크로 따라하기·도전하기 단계별 연습, 음성 안내 → 미리 만든 화면이라 실제 매장 화면과 다름

3.2 관련 연구 및 기술
  1) VizLens(2016)·StateLens(UIST 2019): 휴대폰 카메라로 시각장애인의 손가락을 터치스크린 버튼까지 안내 → 기기마다 화면을 미리 라벨링해야 함
  2) Kong, Guo, Bigham(ASSETS 2019): 고령층이 기기를 비추면 다음에 누를 곳을 AR로 겹쳐 표시 → 화면 구성과 작업 순서를 미리 등록해야 함
  3) GuideMe(CHI 2026): VLM이 휴대폰 화면을 보고 고령층의 스마트폰 사용을 안내해 대면 교육과 비슷한 성과 → 폰 내부 UI 정보를 쓰므로 키오스크에는 쓸 수 없음

3.3 공통점과 차별점 정리
  1) 공통점: 카메라로 사용자를 돕는 점은 Be My AI·Seeing AI·Lookout과, 다음에 누를 곳을 표시하는 점은 VizLens·Kong 외·GuideMe와 같음
  2) 차별점: 기존 서비스는 다음 버튼을 판단하지 않거나(Be My AI·Seeing AI·Lookout), 버튼 위치와 진행 단계를 다루지 않거나(ChatGPT·Gemini), 정해진 화면(연습 앱)·사전 등록한 화면(VizLens·Kong 외)·폰 내부 화면(GuideMe)만 다룸. 본 서비스는 처음 보는 실제 키오스크에서 다음 버튼 판단, 위치 표시, 목표·단계 기억을 모두 지원함
  3) 가져올 점: 답변 피드백(Lookout), 확신이 낮을 때의 대비책(Be My Eyes), 대상 버튼 강조(GuideMe), 다음 누를 곳 표시(Kong 외)

7. 개발 방법론

7.1 모델 선택
  1) 일반 Qwen은 텍스트만 이해하므로, 화면 사진을 이해하는 비전-언어 모델 Qwen2.5-VL 사용
  2) 이미지 속 UI 요소의 위치를 좌표로 출력할 수 있어 버튼 위치 표시에 적합
  3) 공개 모델이라 로컬에서 직접 실행 가능 → 호출당 과금 없음
  4) 7B 모델을 기본으로 하고, GPU 메모리가 부족하면 3B 모델 사용

7.2 단계적 개발
  1) 1단계 – 프롬프트(학습 없음): 사진, 목표, 출력 형식(JSON)을 주는 프롬프트를 설계해 전체 흐름을 먼저 완성
  2) 2단계 – 프롬프트 개선: 단계 판단 → 버튼 선택 2단계 질의, few-shot 예시, 이미지 보정
  3) 3단계 – LoRA 파인튜닝(필요 시): 정확도가 부족하면 수집 데이터로 학습해 전후 비교

7.3 출력 형식
  1) AI는 화면 단계, 다음 버튼, 좌표, 확신도, 안내문, 완료 여부를 JSON으로 출력
  예) {"화면단계": "메뉴 선택", "다음버튼": "커피", "좌표": [120, 80, 260, 140], "확신도": "높음", "안내문": "왼쪽 위의 '커피' 탭을 누르세요.", "완료": false}
  2) 좌표 변환: 모델이 낸 픽셀 좌표를 입력 이미지 크기로 나눠 0~1 비율로 바꾼 뒤 카메라 화면 위에 그림
  3) 검증: 형식·좌표 범위가 틀리거나 버튼을 못 찾으면 다음 장면으로 다시 분석하고, 계속 실패하면 "조금 더 가까이 비춰 주세요"로 안내
  4) 확신도 판단: 모델의 확신도가 "낮음"이거나 두 번 질의한 답이 다르면 상자를 표시하지 않고 다시 분석
  5) 완료 판단: 주문 완료·영수증 출력 화면이면 "완료"를 true로 하고 ④ 완료 화면으로 이동
  6) 실시간 처리: 카메라 화면은 지연 없이 보여 주고, 1초에 한 번 축소 이미지로 직전 장면과 비교해 흔들림이 적고 화면이 바뀌었을 때만 한 장을 AI로 보냄(찍기 버튼 없음). 휴대폰이 크게 움직이면 상자를 숨기고 다시 분석

7.4 데이터
  1) 용도: 기본 방식은 학습하지 않으므로 정답 버튼과 비교하는 평가용으로 쓰고, 파인튜닝 시에만 일부를 학습용으로 사용
  2) 수집: 학교 주변 카페, 패스트푸드점, 영화관 등 매장 10곳 이상에서 키오스크 화면 200장 이상 촬영(9~11주, 각자 매장 5곳 이상). 같은 매장에서 키오스크를 비추는 짧은 영상도 찍어, 앱과 같은 방식으로 자동 선택한 장면 일부(흔들림·기울기 포함)를 평가에 포함
  3) 라벨링: 사진마다 목표와 정답 버튼(이름, 좌표) 표시, 한 사진에 여러 목표 부여(Label Studio)
  4) 분할(파인튜닝 시): 매장 단위로 학습용과 평가용을 나눠, 학습에 쓰지 않은 매장으로 처음 보는 키오스크 성능 확인
  5) 개인정보: 얼굴·결제 정보가 찍히지 않게 촬영, 촬영 전 매장 허락

7.5 평가 지표
  1) 버튼 안내 정확도: 고른 버튼이 정답과 같은 비율(목표 70% 이상)
  2) 위치 정확도: 상자 중심이 정답 버튼 안에 있는 비율(목표 60% 이상)
  3) 응답 시간: 화면이 바뀐 뒤 새 안내까지 걸린 시간(목표 5초 이내, 카메라 영상은 실시간)
  4) 비교 실험: 모델 크기(7B, 3B), 개선 전후(프롬프트 → 개선 → 파인튜닝), 로컬 모델과 상용 API를 같은 평가 데이터로 비교

10. 기대 효과 및 활용 분야

10.1 기대 효과
  1) 디지털 취약계층이 다른 사람의 도움 없이 혼자 키오스크로 주문
  2) 키오스크를 교체하지 않고 사용자의 휴대폰만으로 접근성 향상
  3) 반복 사용을 통해 키오스크 사용법 자체를 익히는 학습 효과

10.2 활용 분야
  1) 병원 접수기, 무인 민원발급기, 공항 셀프 체크인 등 무인기기로 확장
  2) 노인복지관, 디지털배움터의 키오스크 교육 보조 도구
  3) 수집한 키오스크 화면 데이터셋을 접근성 연구에 활용

11. 위험요소와 자료 출처

1) 위험요소와 대응 방안
    (1) 인식 실패(반사·기울기·흔들림, 저시력 사용자의 비추기 어려움) → 흔들림 적은 장면 자동 선택, 가이드 테두리, 이미지 보정, 비추는 방향 음성 안내
    (2) 틀린 버튼 안내 → 확신도가 낮거나 두 답이 다르면 표시하지 않고 재분석, 결제 단계에서 금액 확인 안내
    (3) 응답 지연·서버 부하 → 화면이 바뀔 때만 1초에 최대 한 장 전송, 3B 모델·사진 축소, 구간별 시간 측정, 느리면 찍기 버튼 방식으로 전환
    (4) 시연 중 서버 중단·브라우저 차이 → 시연 전 점검, 상용 API 대체, 실기기 테스트, 음성 인식 실패 시 글자 입력
    (5) 개인정보 → 영상은 저장하지 않고 분석 장면만 전송, 저장 시 동의, 얼굴이 찍힌 사진 제외
    (6) 단순 챗봇으로 보일 위험 → 키오스크 인식·위치 표시·정량 평가로 AI 역할을 보여 줌
