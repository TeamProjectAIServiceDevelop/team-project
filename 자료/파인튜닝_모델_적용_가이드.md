# 파인튜닝한 모델을 앱에 넣는 방법

LoRA 파인튜닝이 끝난 뒤, 그 모델을 평가하고 Ollama에 올려 앱(kiosson.vercel.app)이 쓰게 하는 순서를 정리한다. 학습 방법 자체는 [AI_구현_가이드라인.md](AI_구현_가이드라인.md) 4장을 본다.

```
LoRA 어댑터 → ① 평가(HF) → ② 원본과 합치기 → ③ Ollama에 등록 → ④ 직접 확인 → ⑤ 앱 연결 → ⑥ 스모크 테스트
```

앱 코드는 바꾸지 않는다. 앱은 환경변수 `OLLAMA_MODEL`에 적힌 모델을 부르므로([lib/ollama.ts](../lib/ollama.ts)), 새 모델을 Ollama에 등록하고 이 값만 바꾸면 된다.

## 지금 모델: `kiosk-3b-button` 설치하기 (2026-11-26 학습분)

①~③은 이미 끝났다(이동건, 집 PC). 받은 압축 파일 `kiosk-3b-button-ollama.zip`(4.6GB)으로 **AI 서버 컴퓨터에서** 아래만 하면 된다. 학습·변환 과정과 결과는 `feat/ai` 브랜치의 `finetune/README.md`를 본다.

| 파일 | 내용 |
|---|---|
| `kiosk-3b-button-q4km.gguf` (1.9GB) | 언어 모델, Q4_K_M |
| `kiosk-3b-button-mmproj-f32.gguf` (2.7GB) | 비전 부분. **f32 그대로 쓴다**(f16이면 `888…`만 나온다) |
| `Modelfile` | 위 두 파일 + qwen2.5vl의 대화 형식(TEMPLATE) |

1. AI 서버 컴퓨터에 [Ollama](https://ollama.com)를 설치한다(이미 있으면 건너뜀). NVIDIA 드라이버가 최신이면 GPU를 쓴다. 모델은 GPU 메모리를 약 5GB 쓴다.
2. 압축을 풀고 그 폴더에서 등록한다. 등록한 뒤에는 압축 파일과 푼 폴더를 지워도 된다.
   ```powershell
   ollama create kiosk-3b-button -f Modelfile
   ollama list          # kiosk-3b-button이 보이면 성공
   ```
3. ④처럼 서로 다른 사진 두 장으로 확인하고, ⑤처럼 `OLLAMA_MODEL=kiosk-3b-button`으로 바꿔 다시 배포한다.

확인용 41문항(앱 코드 그대로) 이름+위치: 지금 앱의 7B 14개 → 이 모델 32개, 평균 응답 3.4초 → 1.9초. 다만 확인용 사진이 학습 사진과 같은 매장·같은 키오스크라 처음 보는 매장에서는 더 낮을 수 있다.

## 0. 학습 전에 맞춰 둘 것

이것이 어긋나면 학습이 잘 돼도 앱에서 상자가 틀어지거나 답을 못 읽는다.

| 항목 | 맞출 값 | 이유 |
|---|---|---|
| 학습 사진 크기 | 28의 배수, 약 98만 픽셀(세로 사진은 728×1316) | 앱이 이 크기로 보낸다([app/frame.ts](../app/frame.ts)). 크기가 다르면 상자 좌표가 어긋난다. |
| 1단계(판단) 정답 형식 | `guideSchema` JSON(`stage`, `where`, `steps`, `message`, `done`) | [lib/guide.ts](../lib/guide.ts)의 `parseGuide`가 이 형식만 읽는다. |
| 2단계(위치) 정답 형식 | `{"bbox_2d": [x1, y1, x2, y2], "label": "1"}`, 좌표는 위 사진 크기 기준 픽셀 | `attachBoxes`가 이 형식만 읽는다. |
| 프롬프트 | 앱과 같은 문장(`buildMessages`, `buildLocateMessages`) | 학습 때와 다른 문장을 쓰면 효과가 줄어든다. |

## ① 평가: 파인튜닝 전후 비교 (Hugging Face)

Ollama에 올리기 전에 정말 나아졌는지 먼저 확인한다. 바탕화면의 `HF_평가` 폴더를 쓴다(앱과 같은 프롬프트, 아이폰 15 조건 728×1316).

```powershell
python hf_eval.py                                  # 파인튜닝 전 → results_base
pip install peft
python hf_eval.py --adapter saves/kiosk-lora-3b    # 파인튜닝 후 → results_lora
```

두 폴더의 `summary.md`를 나란히 놓고 비교한다. **학습에 쓰지 않은 매장 사진**으로 평가해야 의미가 있다. 나아지지 않았으면 여기서 멈추고 학습 데이터를 고친다.

## ② 어댑터를 원본 모델에 합치기

LLaMA-Factory로 어댑터를 원본에 합쳐 하나의 모델 폴더로 만든다. `merge.yaml`:

```yaml
model_name_or_path: Qwen/Qwen2.5-VL-3B-Instruct
adapter_name_or_path: saves/kiosk-lora-3b
template: qwen2_vl
finetuning_type: lora
export_dir: merged/kiosk-3b
export_size: 5
export_legacy_format: false
```

```powershell
llamafactory-cli export merge.yaml
```

- QLoRA(4비트)로 학습했더라도 **합칠 때는 4비트가 아닌 원본 모델**에 합친다. 그래서 `quantization_bit`는 넣지 않는다.
- 합친 모델로 `hf_eval.py`를 한 번 더 돌려 ①의 LoRA 결과와 같은지 보면 합치기가 제대로 됐는지 확인할 수 있다(`MODEL` 값을 `merged/kiosk-3b`로 바꿔 실행).

## ③ Ollama에 등록하기

**우리가 실제로 성공한 것은 방법 B(GGUF)다(2026-11-26, Ollama 0.40.16).** Ollama 0.40.12는 `ADAPTER`(LoRA)를 받지 않고, Qwen2.5-VL은 safetensors에서 바로 만드는 것도 지원하지 않아 방법 A는 막힐 가능성이 크다.

### 방법 A: 합친 폴더를 그대로 등록 (우리 모델로는 안 해 봄)

`Modelfile`:
```
FROM ./merged/kiosk-3b
```
```powershell
ollama create kiosk-3b-button -f Modelfile --quantize q4_K_M
```

### 방법 B: GGUF로 바꿔서 등록 (지금 모델은 이 방법)

[llama.cpp](https://github.com/ggml-org/llama.cpp)의 변환 스크립트로 언어 모델과 비전 부분(mmproj)을 각각 GGUF로 만들고, 언어 모델만 Ollama에 들어 있는 `llama-quantize.exe`로 줄인다.

```powershell
python convert_hf_to_gguf.py merged/kiosk-3b --outfile kiosk-3b-f16.gguf --outtype f16
python convert_hf_to_gguf.py merged/kiosk-3b --mmproj --outtype f32 --outfile kiosk-3b-mmproj-f32.gguf   # f16 금지
& "$env:LOCALAPPDATA\Programs\Ollama\lib\ollama\llama-quantize.exe" kiosk-3b-f16.gguf kiosk-3b-q4km.gguf Q4_K_M
```

**비전 부분(mmproj)은 반드시 `--outtype f32`로 만든다.** f16이면 GPU에서 사진에 따라 `888…`만 내거나 답이 끊긴다(CPU에서는 정상이라 헷갈린다).

대화 형식(TEMPLATE)은 지금 쓰는 모델에서 그대로 가져온다.
```powershell
ollama show qwen2.5vl:3b --modelfile
```
출력의 `TEMPLATE`, `SYSTEM`, `PARAMETER` 줄을 복사해 새 `Modelfile`에 넣고, `FROM` 두 줄(언어 모델 GGUF, mmproj GGUF)로 바꾼 뒤 `ollama create`를 실행한다.

### 정밀도 고르기 (언어 모델)

| 정밀도 | 크기(3B) | 메모 |
|---|---|---|
| **Q4_K_M (지금 모델)** | 약 1.9GB | 41문항 이름+위치 32개로 충분히 나옴 |
| Q8_0 | 약 3.3GB | Q4에서 점수가 HF 결과보다 눈에 띄게 낮을 때 |
| F16 | 약 6GB | 원본과 같음. 3060(12GB)에 들어감 |

비전 부분(mmproj)은 정밀도와 상관없이 f32로 둔다(약 2.7GB).

### 막히면: vLLM

Ollama 등록이 끝내 안 되면 vLLM(OpenAI 호환 API)으로 띄운다. 요청 형식이 달라서 `lib/ollama.ts` 옆에 호출 파일을 하나 더 만들고 환경변수로 고르게 해야 한다. 웹 쪽 코드가 바뀌므로 정윤서와 먼저 상의한다.

## ④ 직접 확인

```powershell
ollama list                       # kiosk-3b-button이 보이는지
ollama run kiosk-3b-button
>>> 이 화면의 버튼 글자를 알려 줘 C:\test\a.png
>>> 이 화면의 버튼 글자를 알려 줘 C:\test\b.png
```

**서로 다른 사진 두 장을 연속으로** 넣어 둘 다 한글 버튼 이름이 나와야 한다.

> **`888…`이 나오면:** 11-18에는 Ollama 버전 버그로 보았지만, 11-26에 원인이 **비전 부분(mmproj)을 f16으로 변환한 것**으로 확인됐다. f32 mmproj로 만든 `kiosk-3b-button`은 Ollama 0.40.16에서 정상이다. 받은 `qwen2.5vl:3b`도 같은 증상이 있었다. 이때 앱에는 "화면을 잘 읽지 못했어요"(502)가 뜬다. 위 두 장 확인에서 `888…`이 나오면 `Modelfile`의 두 번째 `FROM`이 `mmproj-f32` 파일인지 먼저 본다.

## ⑤ 앱에 연결

**PC에서 먼저:** `.env.local`
```
OLLAMA_URL=http://localhost:11434
OLLAMA_MODEL=kiosk-3b-button
KIOSK_AI_MOCK=0
```
`npm run dev` → http://localhost:3000 에서 안내가 나오는지 본다.

**배포 주소(휴대폰):**
1. 3060 PC에서 터널을 켠다.
   ```
   cloudflared tunnel --url http://localhost:11434 --http-host-header="localhost:11434"
   ```
2. Vercel → Settings → Environment Variables
   - `OLLAMA_MODEL` → `kiosk-3b-button`
   - `OLLAMA_URL` → 터널 주소(`https://….trycloudflare.com`, 끝에 `/` 없이)
3. Deployments → 최신 배포 ⋯ → **Redeploy**. 다시 배포해야 반영된다.

되돌릴 때는 `OLLAMA_MODEL`을 이전 모델(지금 배포된 앱은 `qwen2.5vl:7b`)로 바꾸고 다시 배포한다. 원래 모델은 Ollama에 그대로 남아 있다.

## ⑥ 스모크 테스트

배포 주소에서 실제로 동작하는지 확인한다.

- 휴대폰으로 https://kiosson.vercel.app/ 을 열고 키오스크 화면(또는 모니터에 띄운 사진)을 비춰 안내와 상자가 나오는지 본다.
- AI 서버 PC에서 `finetune/eval-ollama.ts`(`feat/ai` 브랜치)로 41문항을 다시 채점한다. **이름+위치 32개 안팎이면 정상이다.** 많이 낮으면 ③의 정밀도(Q4 → Q8_0 → F16)나 mmproj가 f32인지 의심한다.

## 문제가 생겼을 때

| 증상 | 원인 | 확인할 곳 |
|---|---|---|
| 503 "AI 서버에 연결하지 못했어요" | 터널이 꺼졌거나 Vercel의 `OLLAMA_URL`이 예전 주소 | 터널 주소를 브라우저로 열어 `Ollama is running`이 나오는지 |
| 502 "AI 서버 오류 (530)" | Vercel이 이미 없어진 터널 주소를 가리킴 | Vercel `OLLAMA_URL` 수정 후 Redeploy |
| 502 "AI 서버 오류 (404)" | Ollama에 그 이름의 모델이 없음 | `ollama list`와 Vercel `OLLAMA_MODEL`의 철자 |
| 502 "화면을 잘 읽지 못했어요", 0.1~0.3초 만에 실패 | 비전 부분(mmproj)이 f16(④ 참고) | `Modelfile`의 mmproj 파일, `%LOCALAPPDATA%\Ollama\server.log` |
| 답은 나오는데 상자가 어긋나거나 전혀 없음 | 앱이 보내는 사진 크기가 바뀜 | [app/frame.ts](../app/frame.ts)가 약 98만 픽셀(28의 배수)로 보내는지. 31만 픽셀로 보내면 상자가 전부 버려진다 |
