# 평가 데이터와 평가 스크립트

키오스크 사진에 정답 버튼을 붙여 두고, AI가 고른 버튼과 비교해 정확도와 응답 시간을 잰다. 스크립트는 앱과 같은 `/api/guide`를 부르므로, 서버 설정(Ollama 7B·3B, 가짜 응답 모드 등)만 바꾸면 같은 데이터로 여러 방식을 비교할 수 있다.

## 폴더 구조

```
eval/
  data/
    <데이터 이름>/          예: 1차, sample
      labels.jsonl          문항 목록 (한 줄 = 문항 하나)
      images/               사진 (jpg, png)
  results/                  실행 결과 (자동 생성)
```

- `eval/data/sample/`은 스크립트 시험용 가짜 화면이다. 실제 평가에는 쓰지 않는다.
- 실제 사진은 용량이 커서 git에 올리지 않는다(`.gitignore`). `labels.jsonl`만 올리고 사진은 팀 공유 드라이브로 주고받는다.

## 문항 형식 (`labels.jsonl`)

한 줄에 JSON 하나. 같은 사진에 목표를 여러 개 붙이면 줄을 여러 개 만든다.

```json
{"id": "cafeA-001-1", "image": "images/cafeA-001.jpg", "store": "학교 앞 카페A", "source": "photo", "goal": "아이스 아메리카노 한 잔 포장", "history": [], "answer": {"stage": "메뉴 선택", "button": "커피", "box": [120, 80, 260, 140]}}
```

| 항목 | 필수 | 설명 |
| --- | --- | --- |
| `id` | 필수 | 문항 이름. `매장-사진번호-목표번호`처럼 겹치지 않게 |
| `image` | 필수 | `labels.jsonl` 기준 사진 경로 |
| `store` | 필수 | 매장 이름. 매장별 정확도를 따로 보고, 파인튜닝 때 매장 단위로 학습·평가를 나눌 때 쓴다 |
| `source` | 필수 | `photo`(사진으로 찍음) 또는 `video`(영상에서 고른 장면) |
| `goal` | 필수 | 사용자가 말한 주문 |
| `history` | 선택 | 이 화면에 오기까지 누른 버튼. 첫 화면이면 `[]` |
| `answer.button` | 필수 | 정답 버튼. **화면에 적힌 글자 그대로** |
| `answer.aliases` | 선택 | 정답으로 인정할 다른 이름. 예: `["Coffee"]` |
| `answer.box` | 필수 | 정답 버튼 상자 `[x1, y1, x2, y2]` (왼쪽 위, 오른쪽 아래). **원본 사진의 픽셀 좌표**, 사진이 똑바로 보이는 방향 기준 |
| `answer.stage` | 선택 | 화면 단계: 처음 화면, 메뉴 선택, 옵션 선택, 장바구니, 결제, 완료 |
| `note` | 선택 | 메모 (반사, 흐림 등) |

### 라벨링 규칙

- 정답 버튼은 **목표를 이루려면 지금 눌러야 할 버튼 하나**다. 여러 개가 가능하면 가장 자연스러운 하나를 고르고 `note`에 적는다.
- 상자는 버튼의 테두리에 맞춰 그린다. 글자만 감싸지 않는다.
- 얼굴, 카드 번호, 영수증 개인정보가 보이는 사진은 쓰지 않는다.
- 두 사람이 서로의 라벨을 검토한다(교차 검토).

### 좌표 따는 법

이미지 뷰어나 그림판에서 마우스를 버튼의 왼쪽 위·오른쪽 아래 모서리에 올리면 픽셀 좌표가 보인다. 사진이 많아지면 Label Studio의 사각형 라벨을 쓰고 결과를 이 형식으로 바꾼다.

## 평가 지표

| 지표 | 정의 | 목표 (Sprint 2) |
| --- | --- | --- |
| 버튼 안내 정확도 | AI가 고른 버튼 이름이 정답(또는 aliases)과 같은 비율. 띄어쓰기·대소문자는 무시 | 70% 이상 |
| 위치 정확도 | AI가 그린 상자의 중심이 정답 상자 안에 있는 비율 | 60% 이상 |
| 응답 시간 | 요청을 보내고 안내를 받기까지 걸린 시간 | 5초 이내 |

AI 서버 오류나 형식 오류로 답을 못 받은 문항은 틀린 것으로 센다.

## 실행

1. 앱 서버를 켠다: `npm run dev`
   - Ollama로 평가: `.env.local`의 `OLLAMA_URL`, `OLLAMA_MODEL`을 맞춘다.
   - 스크립트만 시험: `.env.local`에 `KIOSK_AI_MOCK=1`.
2. 다른 터미널에서 평가를 실행한다.

```bash
npm run eval -- --data eval/data/sample --name mock
```

| 옵션 | 기본값 | 설명 |
| --- | --- | --- |
| `--data` | (필수) | 데이터 폴더 |
| `--name` | `run` | 결과 파일 이름에 붙일 이름. 예: `qwen2.5vl-3b` |
| `--url` | `http://localhost:3000/api/guide` | 평가할 API 주소. 배포 주소도 된다 |
| `--lang` | `ko` | 안내 언어 |
| `--limit` | 전체 | 앞에서부터 몇 문항만 |

결과는 화면에 표로 나오고, `eval/results/`에 문항별 결과(`.csv`)와 요약(`.json`)이 저장된다.
